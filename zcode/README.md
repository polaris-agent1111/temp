# zcode 协作协议（唯一入口）

> 本目录是 Lead（DSH Agent）与 zcode 的**异步任务通道**。
> zcode 每次被唤醒，**只读本文件 + `STATUS.md` + `requests/`**，按需执行，然后写报告退出。

## 0. 一句话规则

**只做 `STATUS.md`「当前需求」里列出的任务；没有需求就什么都不做。**

## 1. 目录结构

```
zcode/
├── README.md              ← 本文件：协议（先读）
├── STATUS.md              ← Lead 维护：当前需求看板（每次先读）
├── requests/              ← Lead 写的任务单（NNNN-标题.md，头部有 status: open|done）
├── reports/               ← zcode 写的交付报告（NNNN-标题.md，与任务单同名）
├── inbox/                 ← zcode 有疑问时写这里；Lead 会来回答（ANSWER-0001.md）
└── templates/task.md      ← 任务单模板（Lead 用）
```

## 2. zcode 每次执行的固定流程

1. 读 `zcode/STATUS.md` 的「当前需求」。若为空或写的是「空闲」→ **直接退出，不做任何事**。
2. 按编号从小到大取任务，读 `requests/<编号>-*.md`；若其 `status:` 不是 `open` → 跳过。
3. 严格执行「允许写的路径」限制，完成后：
   - 在 `zcode/reports/<编号>-*.md` 写报告（模板见任务单「交付」段）；
   - 把任务单头部 `status: open` 改成 `status: done`；
   - 若有阻塞，在 `zcode/inbox/` 写 `Q-<编号>.md`，报告里说明卡点。
4. 退出。不要顺手做别的任务、不要"顺便优化"。

## 3. 硬性红线（违反即视为破坏）

- **禁止登录**任何比赛账号（`47.120.64.152`、`218.2.108.11` 等），禁止提交榜单，禁止修改 `client/secrets.json`、`runs/.session.pkl`。
- **禁止修改** `PLAN.md`、`STATUS.md`（根目录那个）、`client/`、`harness/`、`runs/` 下的任何文件。
- **禁止**删除/移动文件，禁止 `git` 提交，禁止安装系统级软件（包管理器 `apt` 只允许在任务单明确授权时使用）。
- **禁止**探测/攻击任何官方评测系统。绕过规则的行为一律不做。
- 只写：`zcode/` 目录 + 任务单里「允许写的路径」明确列出的文件。
- 遇到密码、token、个人信息：**不写入任何文件、不打印到报告**。

## 4. 报告格式（必须包含）

```markdown
# <编号> 报告：<标题>
- 完成时间：YYYY-MM-DD HH:MM
- 执行者：zcode
- 结论：一句话
## 具体动作
- 命令/步骤（可粘贴关键输出，注意脱敏）
## 产出文件
- 路径（相对工作区根 E:\Download\iDSN）
## 未完成/风险
- ...
## 给 Lead 的建议（可选）
```

## 5. 冲突与并行

- 同一编号的任务**同一时间只允许一个执行者**。你看到 `reports/<编号>` 已存在且任务单 `status: done`，就不要重做。
- 大文件（>200MB）不要下载，先报告。
- 你只负责"杂活"：环境检查、知识调研、文档整理、脚本草稿、报告排版。**核心实验、提交、榜单操作一律由 Lead 做。**

## 6. Lead 如何发布需求

Lead 在 `requests/` 新建 `NNNN-标题.md`（用模板），并把编号加到 `STATUS.md` 的「当前需求」。完成后 Lead 会把编号从看板移除。
