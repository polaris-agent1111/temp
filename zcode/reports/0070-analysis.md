# 0070 报告：QUIC 丢包重传定时器在微突发场景下的退避阶跃函数数理证明

- 完成时间：2026-11-07 04:45
- 执行者：zcode
- 结论：命题精确化后完成两断言证明与三段阶跃函数闭式；**B* = 60 弹性吸收边界三重确认**（队列不变式 + 实测三点 + MC 20000 次/格），但发现关键语义修正——**中段碰撞走 9/8·srtt≈78.8ms 阈值修复（无倍增），只有尾部孤损（文件尾/时钟死亡）才进入 PTO ×2^m 阶跃**；E[PTO 惩罚] = T_PTO/(2p−1)，平台 T_PTO ≈ 78–84ms。

## 具体动作

1. 核对 RFC 9002 原文（rfc-editor.org，2026-11-07）：PTO = srtt + max(4·rttvar, kGranularity) + max_ack_delay；backoff ×2^pto_count、ACK 复位；探测 1–2 包；kPacketThreshold=3、kTimeThreshold=9/8；「已设时间阈值定时器时不得设 PTO」。确认 QUIC 无经典 RTO，一律按 PTO 处理。
2. 编写碰撞事件蒙特卡洛脚本 `zcode/scripts/0070_quic_backoff.py`（纯标准库，仅 stdout）。开发中修正两处建模语义：B>41.7 时不能按每 tick 持续注入（会产生虚假持续饱和）；「时钟死亡」初版条件（k > w0−3）违反 drop-tail 单突发全灭不可能性（引理 2：k < B 恒成立），改为 RFC 忠实的「丢失段后无更高包号被确认（锚点消失）」判据。
3. 证明链：引理 1 弹性吸收（k = max(0, q₀+B−41.7−100)，B*=60，π(B) 闭式：60→0.04%、70→0.47%、80→1.4%、100→3.81%）；引理 2 单突发全灭不可能（q₀ < Q_lim ⇒ k < B）；定理 1 中段碰撞 = 阈值修复步 78.8ms 无倍增；定理 2 尾部孤损 → PTO 阶梯 T_PTO(2^m−1)，E = T_PTO/(2p−1)，p→1/2 悬崖；主定理三段阶跃函数 + 实测 60→70 的 +12.6s 开关归因（级联放大为主、定时器层为下界）。
4. MC 验证：B 组（中段）与 C 组（文件尾 100% PTO 路径）各 8 格 × 20000 试验；q₀ 模型下 p≈1 → 阶梯单步，倍增台阶由闭式覆盖。

## 未完成/风险

- q₀ 分布（U(0,26) + 5%×U(20,60)）为校准近似；实测 burst 70「10+ 丢」对应巨流窗口深部命中，模型给出的 0.47% 概率与之相容但未独立验证 q₀ 分布形状。
- 修复重传的 ACK 往返（+1 RTT）与碰撞期 srtt 膨胀自反馈未建模（方向保守：实际惩罚略高于本文值）；已在 §9 声明。
- 「并拍风险」结论（B≥31 档在唤醒迟滞合并两拍时越过 B*）是推论性分析，未做独立实测验证。

## 给 Lead 的建议

- 主结论支持现有 40/4ms 与 36/4ms 档位的安全性，但提示两点：① 并拍下 40 包档有效突发 80 > 60，是已知方差源，B ≤ 30 档完全免疫（代价是速率）；② 6.bin 收尾阶段最后 1–2 个突发建议偏保守，文件尾孤损是 PTO 的主要现实通道。
- 若需进一步压缩方差，可在 tool 层评估「两拍间最小间隔强制 > 唤醒迟滞」的泄放节奏（需在允许的参数空间内验证，涉及提交额度，由 Lead 决策）。
