# 0261 报告：拥塞窗口突发重置与恢复时延下限分析

- 完成时间：2026-11-07 19:20（更正合并版；并发会话 19:02 首版，本版裁决其证明力并补两态证明）
- 执行者：zcode
- 结论：**「突发重置后恢复 ≤ 2.5 RTT」在桶控旁路机制（我方全部构型默认）下成立——真实候选族 30 点参数网格最坏 1.625 RTT（余量 35%）；在纯 AIMD ACK-clock 下不成立（需 12–18 RTT）**。命题的正确表述是「准开环架构把丢包恢复从 AIMD 时间尺度压缩到 1 次检测 + 毫秒级桶补齐」。

## 具体动作
- 主脚本 `zcode/scripts/verify0261_recovery_bound.py`（stdout → `zcode/scripts/_0261_out.md`，零写入/零网络/零提交）：
  - 态 A（vanilla RFC 9002）：T_A = (1−β)W0/a = 12/15/18 RTT（W0=40/50/60）→ 命题不成立的显式反例；
  - 态 B（准开环桶控 + `enable_n_in_flight` 旁路）：T_rec = T_det(≤1.125 RTT) + G·(1−β)W0/r，在 r∈{36,38,40,42,44} pkt/4ms × W0∈{40,50,60} × RTT∈{4,10}ms 全网格 PASS，最坏 1.625 RTT；
- 复跑并发会话脚本 `quic0261_cwnd_reset_recovery.py`：结果可复现（P99=1.244 RTT），但「恢复=1 RTT ACK+硬编码 0.128 RTT 补齐」使门禁通过属构造保证，且 W0=38 与 RTT=10ms 参数混搭（38 包为 4ms 口径 BDP）——保留为单点参数化参考，不作为证明依据；
- 理论审计落盘 `docs/analysis/0261-theory-audit.md`（含对 19:02 版的技术裁决表），交叉引用 0086 开环确界 0.464C、0087 cwnd 切换连续性 ≤0.47s、0253 PTO 死锁仿真。
