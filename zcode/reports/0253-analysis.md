# 0253 报告：极端高丢包 5%~10% 环境下 QUIC 发送窗口抗死锁验证
- 完成时间：2026-11-07 18:3x（Asia/Shanghai）｜ 本报告为合并版（初稿 18:04 + 扩展验证 18:3x）
- 执行者：zcode
- 结论：两套独立仿真一致证实 —— p ∈ {5%, 7.5%, 10%} 双向/单向丢包下传输完成率 100%（1800-run 分布验证 + seed-42 确定性验证，后者本执行已重跑复现）、全局最小 cwnd=2（RFC 9002 §7.2 下界）、PTO 链实测 ≤3、最大无进度 stall 0.22s vs 空闲超时 30s（136 倍裕度）、死锁 0 次。「100% 存活」达成。

## 具体动作
- 扩展验证脚本 `zcode/scripts/ptt0253_quic_pto_liveness.py`（本执行编写并运行）：
  - 双向独立丢包（数据+ACK，ACK 不聚合最坏化）× 三 CC 谱系（reno/bbr/开环 pacer 上界）× 3 丢包率 × 200 runs = 1800 runs，固定种子；
  - 结果：9/9 格 100% 存活；reno 完成时间 50.9/66.7/81.8s（p=5/7.5/10%，Mathis 交叉核对 1.607 vs 预测 1.414，+14% 偏差来自 cwnd=2 地板）；bbr/开环 1.3–1.6s；
  - 消融实验：去掉 RFC 9002 §6.2.1「ACK 复位退避」条款 → PTO 间隔指数失控（78ms→79.9s）→ reno 200/200 全灭；恢复条款 → 100% 存活。证明抗死锁 = §7.5（探针不受 cwnd 阻塞）+ §6.2.1（退避复位）双条款缺一不可。
- 复现初稿脚本 `zcode/scripts/quic0253_loss_deadlock_defense.py`（单次确定性验证，单向丢包 seed 42）：5/8/10% 下完成 True、min CWND=2、PTO 612/1092/1403 次、死锁 0 —— 与初稿报告数字逐一吻合。
- 合并说明：初稿（18:04 落盘）为单次 run、单向丢包模型；本执行补足双向 ACK 丢失（真正死锁触发面）、分布规模（n=200/格）、stall 裕度定量与消融分析，两套结果方向一致、结论相同，均已如实并列写入审计文档。
- 诚实边界：存活 ≠ 有成绩。p=10% 下 loss-based CC 外推 6.bin（320MB）需 ~2618s > 600s 评测界（吞吐饥饿，与 0086 同源）；官方 leak 构型尾损 0.157% 比压力带低 32~64 倍，属裕度认证而非现实工况。
