# 0076 报告：官方系统调度周期微秒级底噪对 Linux hrtimer 纳秒时钟源别名扰动分析

- 完成时间：2026-11-07 04:55
- 执行者：zcode
- 结论：噪声不打在时钟读数上而打在唤醒路径上——ns 记账 × ms 唤醒迟滞产生确定性「调度别名」，且按模块二分：**precise（schedule 型）速率守恒但迟滞转化为聚簇**（0.8–1.2ms 迟滞→10.5–12 包；jiffy 4ms 回退→40.5 包=缓冲尺度整数共振），**leak（interval 型）平滑但速率折损**（4000µs+迟滞→80% 有效速率，复现 0068 的 77–87%）。clock_granularity=1000µs 贪读语义本身提供 g/τ_p≈10–11 包聚簇下界。稳态后果：后台突发丢包阈值从理想 28.5 包被侵蚀至坏相位 18.5 包（−24 KB）；**96M+4% 余量恰好吸收该侵蚀**（11.5 底噪+20 聚簇残差仍 <40 缓冲），与 0075 膝点/0072 方差稳健/0066 平坦区四方同向。

## 具体动作

1. 建立噪声底清单（TSC 1ns 读数 / LAPIC ~1µs / slack 50µs / 实测唤醒迟滞 0.8–1.2ms / jiffy 4ms=0013 的 G 锚 / cgroup 100ms），并给出别名命题：hrtimer ns 精度只覆盖记账，发射时刻精度由唤醒路径决定。
2. 编写并运行 `zcode/scripts/alias0076_hrtimer_noise.py`（确定性 MC）：precise 释放模式仿真证明**速率守恒**（96.00 Mbps 恒定）且迟滞→聚簇（10.5–12 包）；贪读语义给出 g/τ_p≈11 包下界；共振分类表（1ms/4ms/100ms 与 τ_p 全为整数比 → LOCKED，4ms 恰为 40 包=缓冲尺度）。
3. 双机制对照：leak 4000µs+迟滞 → 76.8 Mbps（80%），独立复现 0068 的 77–87% 折损锚点；precise 同迟滞速率守恒——为 0068 模块族对比（leak 长文件 +3–3.7pp）提供机理基础。
4. 队列级侵蚀表：M/D/1 底噪 11.52 包（0066）+聚簇残差 → 后台突发丢包阈值 28.5→18.5（10 包聚簇）/8.5（20 包）/负值（jiffy 回退必然丢包区）；会话级联合上界 0.56 事件/场（标注为松上包络）。
5. 工程含义：clock_granularity=1000µs 默认值承重（维持）；「亚 G 间隔 ≥4000µs 铁律」（0013）在 schedule 型一侧的镜像推论成立；enable_n_in_flight 旁路是唤醒迟滞的管道级补偿。
