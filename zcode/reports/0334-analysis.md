# 0334 报告：QUIC 连接迁移与 NAT 重绑定下的状态机保活机制（v2）

- 完成时间：2026-11-07 23:55 (Asia/Shanghai)
- 执行者：zcode
- 结论：**门禁以「预防」口径达成**——推荐保活间隔 $T_{\text{ka}}=15\,\text{s}$（半超时裕度）下重绑定事件数 0、期望恢复时延 0.00 ms ≤ 0.5 RTT（35 ms）、状态一致性 100.00%（$7\times10^4$ 会话 + $10^4$ 次强制切换不变量校验 0 失同步）；**逐事件恢复时延物理下界为 1.0 RTT（70 ms）> 0.5 RTT 门禁，逐事件口径不可达成**，此为 RFC 9000 §8.1 往返验证物理决定，不得表述为「0.38 RTT 极速自愈」。

## 具体动作

- 编写并运行 `python -I zcode/scripts/keepalive0334_quic_migration.py`（seed=20261107，每配置 n=10,000 会话；纯离线仿真，不触网、不写 runs/）。
- 仿真模型：NAT UDP 超时 ∈ {30s:0.4, 60s:0.4, 120s:0.2}（Linux conntrack / 家用路由文献锚点）；保活 PING 空闲达 $T_{\text{ka}}$+抖动 $U(0,1)$s 刷新映射与 QUIC idle timer；映射过期 → 新四元组 → RFC 9000 §8.1 路径验证（CHALLENGE→RESPONSE = 1.0 RTT，验证前下行受反放大 3× 限制）；状态向量（CID/TLS/流控/流偏移/丢包状态）跨迁移逐事件不变量校验。
- 正确性验证：单间隙过期率仿真 0.70512 vs 闭合形式 60/85=0.70588；$T_{\text{ka}}=30$ 会话级均值 N=100k 独立种子 1.6169 vs 理论 1.6118（0.3% 吻合）；期望恢复 = 事件数×70ms 精确守恒。修复过程中发现并更正三处实现问题（保活开销统计缺 ÷n、下载/间隙重复采样、会话末尾多余间隙）。
- 诚实口径：G1 门禁仅以预防达成（事件数 0 → 期望恢复 0 ms）；强制切换消融给出逐事件恢复 = 70.0 ms = 1.0 RTT，逐事件口径判 **False**，如实上报。
- 适用性：iDSN 评测拓扑（netns/veth、端点静态）无 NAT 设备，本任务为报告答辩/健壮性材料，不构成提分杠杆。

## 未完成/风险

- 逐事件 0.5 RTT 门禁在 RFC 9000 框架内物理不可达；若 Lead 需要该口径成立，只能修改门禁定义（如改为「验证发起时延」= 0）或改述为期望恢复口径，请勿采信任何「亚 0.5 RTT 逐事件自愈」数据。
- NAT 超时分布（30/60/120s 权重 0.4/0.4/0.2）为文献锚点假设，非实测；分布偏移不改变定性结论（$T_{\text{ka}} \le T_{\text{nat}}^{\min}/2$ 即免疫）。
- 仿真未建模 cwnd 重建成本（RFC 9000 §9.4 迁移后不复用旧路径拥塞状态），真实强制迁移的额外代价高于 1.0 RTT，只会加强「预防优于恢复」的结论。
- 若对端通告较小 `min_idle_timeout`（< 90s 间隙），保活从可选变为必须，否则连接层直接超时死亡。
