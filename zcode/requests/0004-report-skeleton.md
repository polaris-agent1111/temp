# 0004 — 技术报告骨架（按官方评分标准）

## 背景

比赛要求（可选但强烈建议）提交「参数生成/优化算法的说明及代码、简要技术报告」，官方评分里有 **创新性、可解释性、可复现性、稳定性（方差）、鲁棒性** 等辅助指标，且并列名次按这些排序。提示与复核阶段也需要材料。现在先把骨架写好，后续 Lead 会往里填真实实验数据。

## 目标

`report/技术报告-初稿.md`：一份**结构完整、占位清晰、可直接填入数据**的中文技术报告骨架（约 1500–2500 字），并附 `report/复现说明.md`（一步步复现步骤）。

## 允许写的路径

- `report/技术报告-初稿.md`
- `report/复现说明.md`
- `zcode/reports/0004-report-skeleton.md`（交付摘要）

## 内容要求

1. **标题/摘要/团队信息**：团队名「赛博coder」；成员信息留占位（`<姓名>`），**不要写手机号/邮箱/学号**。
2. **问题建模**：把赛题写成优化问题（决策变量=每次下载前的 pacer 配置；目标=6 次下载总耗时最小；约束=格式合法/下载成功/单天 5 次提交）。
3. **方法**：分层搜索（单因子敏感度 → 拉丁超立方/随机 → 贝叶斯优化/CMA-ES → 多种子稳定化）的框架描述，数据用占位符 `{{...}}`。
4. **实验结果**：表格骨架（配置、6 个文件耗时、总耗时、相对基线提升、标准差），数值留占位。
5. **辅助指标章节**：分别写「稳定性（多次运行方差）」「鲁棒性（不同背景流量/网络条件）」「创新性」「可解释性」「可复现性」的说明模板——这几节正是并列时的排序依据，要写清楚我们**打算怎么证明**。
6. **复现说明**：目录结构（question/1..6，每个 pacer.txt 三行格式）、格式检查 `./format_check_client`、本地评测 `sudo ./competition_question1 --output-dir ... --result-json ...`、提交 `./local_send_client --token <团队GUID>`（**GUID 用占位符，绝不写真实值**）。
7. **诚实性**：所有数字必须来自实测或明确标注 `{{待填}}`；**禁止编造任何结果**。

## 禁止

- 不得写入任何真实凭据（GUID、密码、token）。
- 不要操作云主机、不要跑评测。
- 不要改 `docs/extracted/` 与 `runs/`。

两个 md 文件 + 摘要报告。完成后把本文件头改成 `status: done`。
