# 0022 — 技术报告 v4：补「间隔维度」与「本地环境漂移」两个方法论发现

## 背景

`report/技术报告-v3.md` 之后又产生了两条**有方法论价值**的发现，必须进正式报告（复核/答辩都会问「你们怎么知道本地结果可信」）：

1. **间隔维度**：保持包速率不变（6000 包/s），把 `leak_interval_us` 从 4000 拉到 5000/6000/8000：
   - `30/50/5000` = 118.31 / 112.30 / 118.81 / 124.31 / 132.07（多次；均值约 121）
   - `36/50/6000` = 131.04（n=1）
   - `48/60/8000` = 126.22（n=1）
   - 结论：**5 ms 是本地最优间隔档**，且 5 ms 对官方定时器粒度（≈4 ms 反推值）更宽容。
2. **本地环境漂移**：同一配置 `30/50/5000` 在 20:33–21:15 的 4 次评测为 118.31 / 112.30 / 132.07 / 124.31，**极差 19.8 s**；`24/50/4000` 全天在 119.6–138.1 之间。由此确立一条实验规范：**跨时段比较不可用，必须同段交错 A/B**（这也解释了为什么早期「122.07±1.71」是假象）。

## 目标产出

`report/技术报告-v4.md`（新建，不覆盖 v3），在 v3 基础上：

1. **新增 §2.4「间隔维度扫描（v4 新增）」**：把上面 3 个配置的实测写成表 + 结论（5 ms 最优、等速下间隔越长越抗定时器粒度但突发更大）。要注明 n=1 的配置不可作为结论依据。
2. **新增 §2.5「本地环境的时段漂移与交错 A/B 方法」**：给漂移证据（同配置 19.8 s 极差）、时间线表、以及方法论结论（同段交错、n≥3、跨时段数据不可比）。并说明这条规范如何改变了我们对早期结论的判断（`24/50` 从 122.07 修正到 127.01）。
