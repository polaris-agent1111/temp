# 0014 — 提交台账 + 到 11/16 的每日提交排期

## 背景

比赛每天 5 次提交额度，超过 8 次可能封号（`实验详细手册.md:163`）。截止 **2026-11-16 23:59:59** 榜单冻结，11/18 前复核，11/20–22 厦门现场答辩/颁奖。今天（11/05）已用满 5 次。需要一份台账 + 排期，保证剩下 11 天每天额度用满且不浪费、不封号。

## 目标产出

`report/提交台账.md`，包含：

1. **已提交台账表**：从 `runs/submissions.jsonl` + `intel/raw/leaderboard_*.json` 汇出，列：
   `提交时刻 | 配置摘要(local 均值) | 官方成绩 | 官方/本地比 | 结论/收获`。当前应含 v1 / v1b / S3 / S4 / S5 五条（S5 可能还没出分，标「待出分」）。
2. **官方成绩随时间的曲线**（我们队 vs 榜首）：用 attempts 数据，标出每次提交的配置族（leak1ms / tb / leak4ms）。
3. **排期表**：11/06–11/16 每天一行，列：
   - 当天要验证的科学问题（每天最多 1–2 个）
   - 计划提交的配置族/参数（给具体值）
   - 预期排名变化
   - 风险与回退方案
   要求：前期（11/06–11/10）偏「探索」（每天 3 探索 + 2 打最好配置），后期（11/11–11/15）偏「收敛」（5 发全打当前最优配置吃官方随机性），11/16 只投最优配置且不冒险。
4. **额度安全规则**：每日硬上限 5；跨日不要连发；出错（格式检查失败）也算额度，所以提交前必须先跑格式检查；记录每笔状态。
5. **风险清单**：官方出分延迟 10–60 min、官方 3 次取平均仍可能整体抖动、top 提交会被人工复测（防过拟合）等，各给应对。

`runs/submissions.jsonl`、`intel/raw/leaderboard_*.json`、`intel/analysis/board_timeseries.csv`、`STATUS.md`、`hourly/INDEX.md`、`docs/analysis/leaderboard-timing.md`。
