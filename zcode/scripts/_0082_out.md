# 0082 计算输出 — veth+TC 微延迟解构与瓶颈队列仿真

## A. 逐跳微延迟预算（公开内核语义锚，µs）

| 跳 | 下界 | 上界 |
|---|---|---|
| QUIC sendmsg → UDP 栈（syscall+校验和） | 1.0 | 3.0 |
| dev_queue_xmit → qdisc enqueue（无锁快速路径） | 0.5 | 2.0 |
| qdisc dequeue（tbf/netem 定时器驱动时另计 hrtimer 精度项） | 0.5 | 5.0 |
| veth_xmit：sk_buff 复制/转发到对端（~1.3KB） | 1.0 | 3.0 |
| 对端 netif_rx → NAPI/softirq 调度（空闲态） | 2.0 | 30.0 |
| softirq 背载态退化项（CPU 争用时） | 0.0 | 200.0 |
| IP/UDP 解栈 + socket 分发 | 1.0 | 5.0 |
| **固定路径合计** | **6.0** | **248.0** |
| 单包串行化 @100Mbps（W=1271B，skb 域） | 101.7 | 101.7 |

**量级结论**：veth+TC 固定路径 6–248 µs（其中仅 ~3µs 发侧开销与瓶颈串行化相加，接收侧 µs–百 µs 项与瓶颈服务并行）；单包串行化 101.7 µs 才是逐包硬成本。µs 级路径延迟对 4ms refill 网格 / 100µs pacing 网格均 <2%；**排队物理由串行化 + 爆发动态主导，veth 路径成本不构成瓶颈**——官方实测 133s≈本地（0013）与此一致。

## D. TC shaper 计时后端与 0081 对接

| shaper | 计时后端 | 粒度 | 对接结论 |
|---|---|---|---|
| tbf | 老内核 jiffies 粗定时器 → 新内核 hrtimer | 4ms / ns | 若官方 jiffies 后端：瓶颈限速本身锁 4ms 网格 → 与我方 refill 同相位共振（0081 §一）|
| netem | hrtimer + rbtree 延迟出队 | ns | 限速精度足够；排队延迟由延迟出队队列决定，同 B 表 |
| htb | 内部令牌 + 类量子调度（500µs~10ms） | 类量子 | 41 Mbps 份额与 htb class 量子化行为相关 |
| fq/fq_codel | EDT + hrtimer | ns | pacing 网格由 EDT 决定 |

**核心交叉发现**：若官方瓶颈限速器为 jiffies 后端（tbf/htb），则**瓶颈服务节拍与我方 refill 同时锁在 4ms tick 相位**——0081 的相位锁定不仅作用于我方发射，也作用于瓶颈；两相位差恒定 → B/C 表的延迟/丢包是确定性周期模式，官方「重复多次取平均」的方差因此可预测（服务稳定时段 → 方差小；相位冲突时段 → 方差放大）。
