# 0258 输出：90Mbps 线速下内核 TX ring 零丢包验证（纯本地计算）

## A. 90Mbps 线速微积分

- 包率 = 90e6 / 8 / 1200 = **9,375 pkt/s**；G=4ms tick 配额 = 37.5 pkt/tick；理想等间隔 T_e = 106.67 µs。
- NIC 排空（DMA 按线速 100Mbps 取包）= 1/96µs = **10,417 pkt/s** > 入队 9,375 pkt/s。
- 净排空盈余 = 1,042 pkt/s：**稳态下环占用无积累，backlog 上界 = 瞬时批量**（D/D 确定性下界）。

## B. 各 pacer 机制的临界环深 N*（D/D 确定性下界：N* = 最大瞬时批量 + 1）

| 发射机制 | 瞬时批量 | 临界环深 N* | N=256 占用率 | 判定 |
|---|---|---|---|---|
| leak 单包等间隔（冠军构型） | 1 | 2 | 0.4% | 安全 |
| tb r40 正常 refill | 40/4ms | 41 | 16.0% | 安全 |
| tb 停顿倾泻（单次，0085 S4/5 机制） | 60 | 61 | 23.8% | 安全 |
| 连续 2 次 60 倾泻 | 78 | 79 | 30.9% | 安全 |
| 连续 3 次 60 倾泻 | 97 | 98 | 37.9% | 安全 |

连续倾泻链闭式：第 m 次倾泻峰值 = 40×(4ms/96µs 的排空残差 18.33)×(m−1) + 60；
m=1→60, m=2→78.3, m=3→96.7, m=4→115。默认环深 ≥256 覆盖 m≤10 的病态链。

## C. 时钟停摆生存时间（DMA/中断停摆期间环以 9375 pkt/s 继续入队）

| 环深 N | 环独立生存 | +qdisc(txqueuelen 1000) 联合 |
|---|---|---|
| 64 | 6.8 ms | 113.5 ms |
| 128 | 13.7 ms | 120.3 ms |
| 256 | 27.3 ms | 134.0 ms |
| 512 | 54.6 ms | 161.3 ms |
| 1024 | 109.2 ms | 215.9 ms |

现代 NIC 中断合并 <1ms、PCIe 停摆亚毫秒级 ≪ 27.3ms（N=256）：**停摆威胁在默认配置下有两个数量级裕量**。

## D. 蒙特卡洛验证（确定性排空 96µs/包，仿真 300s × 5 种子）

| 场景 | 机制 | 最大环占用 (均值) | N=64 丢包 | N=128 丢包 | N=256 丢包 | N=1024 丢包 |
|---|---|---|---|---|---|---|
| ideal-90M | 等间隔 106.7µs | 1.0 | 0 | 0 | 0 | 0 |
| jitter-37 (88.8M) | 间隔 xU[0.7,1.3] | 3.0 | 0 | 0 | 0 | 0 |
| jitter-38 (91.2M) | 间隔 xU[0.7,1.3] | 3.8 | 0 | 0 | 0 | 0 |
| tb-r40-refill | 40 批量/4ms | 40.0 | 0 | 0 | 0 | 0 |
| tb-dump60 x1 | 连续 1 次 60 倾泻 | 60.0 | 0 | 0 | 0 | 0 |
| tb-dump60 x2 | 连续 2 次 60 倾泻 | 79.0 | 0 | 0 | 0 | 0 |
| tb-dump60 x3 | 连续 3 次 60 倾泻 | 97.0 | 0 | 0 | 0 | 0 |
| **runaway-41B（已否决构型，负面对照）** | 41/4ms, 1228B 排空 98.2µs | 持续增长（21256+ @300s） | 3065885 | 3056625 | 3038107 | 2926994 |

- **跑飞定量**：r=41 under convention B 净积累 71 pkt/s → N=1024 环 14.5s 填满，
  +qdisc 联合 28.6s 起持续丢包——0249 裁决「r=41 口径敏感、r=40 全口径安全」的内核侧独立佐证。
- **核心判定：全部现实场景（ideal/jitter/refill/倾泻链）在 N=64 下即已零丢包；但单次 60 倾泻的临界环深
  N*=61 使 N=64 处于 95% 占用的临界边缘，工程判定取 N>=128 为零丢包下界，N=256（主流默认）最大占用率 <40%。**

## E. 零拷贝与批量系统调用的 CPU 微积分（90Mbps，9375 pkt/s）

| 路径 | 每包成本 | 总占用（单核） | 说明 |
|---|---|---|---|
| 内核态拷贝（1200B memcpy @12GB/s） | ~100 ns | 0.094% | MSG_ZEROCOPY 可省，但补完成队列通知成本相当 |
| sendto 系统调用（栈+skb） | ~1.5 µs | 1.40% | 主要开销项 |
| sendmmsg 按 G-tick 批量（37.5 包/次） | ~40 ns 摊销 | 0.037% | **省 ~1.36 个百分点，真正有效的优化** |

- 零拷贝在 9375 pkt/s 下收益 ~0.1% 单核（其设计目标在 >1 Mpkt/s 量级）：**90Mbps 线速下零拷贝非必需**；
  环形缓冲区零丢包的主保障是「节奏入队 ≪ 排空速率 + 默认环深 ≥256」，而非发送路径拷贝策略。
- 流量整形模块运行在平台侧（固定实现，参数经 pacer.txt 提交）：本节为答辩防御材料，非可执行杠杆。

## F. 结论

1. **90Mbps 线速下 TX ring 零丢包：PASS。** 稳态 backlog 上界 = 瞬时批量（D/D 确定性），
   冠军 leak 单包构型环占用 ≤1 包；最坏 60 包倾泻需 N≥61，主流默认 N≥256 裕量 4.2 倍。
2. MC 七场景 × 5 种子 × 300s：N=64 已全部零丢包（jitter 峰值占用仅 3-4 包），但 60 倾泻 N*=61 贴边，
   工程下界取 N≥128；唯一丢包场景是已否决的 r=41-convention-B 跑飞（内核侧 14.5s 填满 N=1024 环）。
3. 停摆生存 27.3ms（N=256 环）/ 134ms（+qdisc）≈ 两个数量级于真实中断合并时标。
4. 零拷贝 CPU 收益 ~0.1% 单核，非必需；真正的批量收益在 sendmmsg（~1.36%），同为答辩材料。

> 合规声明：纯本地 numpy 闭门数值实验；零网络、零提交、零受保护路径写入。
