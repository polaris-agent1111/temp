# 官方探测计划（11/06 – 11/16，55 发）

> 核心前提（11/05 已证实）：**官方评测用固定随机种子 ⇒ 同一配置成绩近似确定**（v1/v1b 两次只差 0.83%）。
> 所以**重复投同一配置没有收益**，每天 5 发应作为 **5 次不同配置的探测**；榜取最好，不会因投差配置而受损。

## 每天固定流程

1. **00:05**（额度重置后）：`python tools/night_submit.py --plan runs/submit_plan_<MMDD>.json --at now`
   或先写好当天的 plan 文件，让 `--at "YYYY-MM-DD 00:05"` 定时执行。
2. **出分后**（延迟 10–60 min）：`python tools/official_log.py` → 刷新 `runs/official_results.jsonl`，看哪个族官方最好。
3. **更新**：`hourly/INDEX.md` + 当天 `hourly/YYYY-MM-DD_HH00.md`。
4. **失败处理**：若提交报「已达到最大提交次数」，说明额度边界不在 00:00，等 10–20 min 重试；若报格式失败，立即停投（格式失败也扣额度）。

## 阶段划分（按探测目标）

| 阶段 | 日期 | 目标 | 每天 5 发的构成 |
|---|---|---|---|
| 探索期 | 11/06–11/08 | 摸清官方响应面：速率维度、cap 维度、官方放大系数 δ | 3 发在 22–24 速率区间、2 发在相邻区间（20 / 26 / 28）或 cap 变化 |
| 机理验证期 | 11/09–11/10 | 验证「4 ms 定时器粒度」模型（用 interval=2000 的等速率配置做判别）+ 试 interval 5000/6000 | 2 发理论判别 + 3 发当期最优 |
| 收敛期 | 11/11–11/13 | 在官方最优族内做 ±1 步精调（rate ±1、cap ±5） | 4 发精调 + 1 发机动（盯对手有新纪录时对标） |
| 锁定期 | 11/14–11/15 | 只投官方实测最好的 2–3 个配置 | 5 发全部投已知最好，不再试新 |
| 末日 | 11/16 | 只投最稳配置，不冒险（冻结前最后一发留出出分时间） | 5 发同族，17:00 前投完（留 7 小时出分） |

## 已知约束（不许违反）

- 每天 ≤5 发；**超过 8 发可能封号**。格式检查失败也扣额度，所以每次提交前必须先过 `format_check_client`（`submit_batch.py` 已内置）。
- `leak_interval_us` 必须 ≥ 4000（1 ms 会被官方定时器粒度腰斩到 2×）。
- `bucket_cap ≥ leak_rate`；`burst ≥ tokens`；参数名不能写错。
- top 提交会被人工复测（换种子），**不要针对固定种子过拟合**——配置要在多种子下都稳（本地 n≥3 均值 + 方差小）。

## 停止条件（防止无意义消耗）

1. 累计 15 个官方探测点后仍 >129.0 s → 放弃一等，转而稳二等/三等奖，把额度用于防守（对手追近时投最优配置）。
2. 11/12 前始终没有 ≤131.27（二等奖线）→ 全力保前 6（三等奖）。
3. 11/15 仍没进前 6 → 末日只投最稳配置，不再试新。
4. 任何时刻对手刷出比我方最好成绩快 3 s 以上的新纪录 → 当天的机动发对标其配置族。

## 11/06 首轮设计（已写入 `runs/submit_plan_1106.json`）

## 11/07 自适应设计（按 11/06 官方结果分支）

设 11/06 官方最好者为 (rate*, cap*)，则 11/07 的 5 发：

- **分支 A（官方最好在 rate=22，即曲线单调下降）**：rate 18 / 20 / 22 / 22 / 22，cap 分别 50 / 50 / 50 / 55 / 45
- **分支 B（官方最好在 rate=24，即谷底在中）**：rate 23 / 24 / 25 / 24 / 24，cap 分别 50 / 50 / 50 / 55 / 45
- **分支 C（官方最好在 rate=26，即曲线单调上升）**：rate 26 / 27 / 28 / 30 / 26，cap 分别 50 / 50 / 50 / 50 / 60
- **分支 D（三个 rate 官方成绩差 <1.5 s，说明 rate 不敏感）**：转向 cap 维度与 interval 维度（40/50/60/70/80 或 4000/5000/6000）

判据：官方成绩差 <1.5 s 视为噪声级（官方同配置重投差 0.83% ≈ 1–2 s）。

## 若官方成绩普遍比本地差 +10% 以上

说明官方环境不是「等价」而是「更慢」，此时本地排序不可直接迁移：应改用**官方架构下的相对排序**来决定主攻（即只看官方成绩排前 3 的配置族，在其邻域继续探测），并重新估计「要拿第一需要多少秒」。
