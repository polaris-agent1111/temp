# 复核材料包 v2（赛博coder · 六载穿柜）

> 一页说明：我们做了什么、怎么复现、目录导航。v2 更新于 2026-11-05（整合「官方定时器粒度」发现与 4 ms 推荐配置）；凭据类信息（团队 GUID、密码）一律占位。

## 我们做了什么（一段话）

赛题要求为 6 个依次下载的文件（10→320 MB，共 630 MB）在共享 100 Mbps 链路 + 100 Mbps 网页搜索背景流量下配置 QUIC 流量整形参数，使总耗时最短。我们以链路预算分析定位瓶颈（79% 损失在 4/5/6 号大文件的稳态份额），用「对照 → 单因子 → 网格 → 复测选型 → **跨环境标定**」的分层搜索完成 108 次有效本地评测：本地从基线 170.0 s 降至 126.9 s 量级；**官方评测中我们发现并量化了「评测机定时器实际粒度 ≈ 4 ms（反推值）对 1 ms 漏桶配置的速率腰斩」这一关键约束（同配置官方 244–246 s vs 本地 124 s，两次复现），将漏出间隔抬到 4000 µs 后官方回到本地水平，最好成绩 133.086 s（榜第 5）**——发现过程与定量模型见 `docs/knowledge/timer-granularity.md`，本包即按该结论整理的复核材料。

## 怎么复现（三步）

1. **看配置**：`best-configs/` 内 5 个候选——**复核推荐用 4 ms 两个**（`leak-36-40-4000` 有官方 133.086 实测背书；`leak-24-50-4000` 本地最优），原三个为历史对照（其中 `leak9-rate9` 是 1 ms 陷阱样本，官方复测禁用）。
2. **跑评测**：按 `reproduce.md` 把任一候选放入云主机 `question/1..6`，先 `./format_check_client` 再 `./competition_question1`（4 核及以上，单次 2.5–4 分钟）；**⚠ 必须用 `leak_interval_us ≥ 4000` 或带 `enable_n_in_flight` 的模块**（见 reproduce.md 专节）。
3. **算统计**：工作区执行 `python tools/config_stats.py` → 重生成 `report/实验结果-统计.md` 第 1–4 节；官方模型复算 `python tools/timer_model.py fit`；数据源 `runs/results.jsonl`（120 条/108 有效）。
