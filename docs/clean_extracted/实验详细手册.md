# 实验详细手册

实验手册（通用）

本手册用于帮助参赛者如何使用本竞赛平台提供的虚拟仿真平台，以及在虚拟仿真平台中如何完成实验的运行、提交和评估等相关操作，请参赛者在正式开展实验之前，详细阅读本手册。

本手册适应场景：当参赛者进入具体赛题页面进行比赛答题时，在正式开展实验之前，请阅读本手册以做好相应准备工作。

如上所示，虚拟环境（云主机）的桌面中，存在这如下四个文件/文件夹：

提交目录（question目录），参赛者需要将本次竞赛的网络协议参数配置放入此目录中，然后本地的仿真实验执行程序将会从该目录中读取协议参数配置并进行应用及评估，以及各参赛者最后会将该目录存放的网络协议参数配置通过本地客户端发送到服务端处进行评估。简而言之，各参赛者需要将所构建的网络参数配置放入到该目录进行本地评估以及上传到远程服务端。

格式检查程序，检查提交目录（question目录）中目录结构、所存放的网络协议参数配置内容其格式规范是否合法，一次检查将会反馈全部不符合项。

仿真实验评估程序，该程序将会直接读取提交目录（question目录）中的协议参数配置，并在仿真实验中（如文件下载实验）对这些参数配置进行仿真实验评估（本地评估），并反馈出最终的实验结果。

本地发送客户端，将提交目录（question目录）进行打包，并发送到远程服务端处进行评估。

2.2 提交目录（question目录）

在竞赛中，各参赛者的最终成果就是自己构建的各协议参数配置，本平台提供了一个指定名称路径的目录（/home/openlab/Desktop/question），要求各参赛者将竞赛过程中所生成/构建的协议参数配置统一放入该文件目录中，提交目录（question目录）的结构如下：



如上所述，提交目录（question目录）中包含5个子目录【具体赛题不一样，子目录的个数也是不一样，这里仅作为示例讲解】：1~5，每个子目录就代表每次文件下载时要使用的协议参数配置，或者说每个子目录中存放着每次文件下载要使用的协议参数配置文件。如子目录1就代表在仿真实验中，客户端向服务端下载第一个文件要使用的协议参数配置（通常该协议参数配置主要作用于服务端处，用于修改服务端处的协议参数配置），同理可知，子目录5就是第五次下载文件时要采用的协议参数配置。

具体于各个子目录而言，各子目录中存放着就是参赛者所生成/构建的各种协议参数配置文件，比如流量整形的参数配置文件“pacer.txt”等，至于各个子目录中到底应当（可以）存放什么样的参数配置文件，这就要看具体赛题的要求了，比如对于流量整形相关的赛题，它仅可允许各子目录中存放流量整形模块相关的参数配置文件“pacer.txt”。

至于各协议参数配置文件中填写的内容规范，需要参阅赛题的要求以及相应API使用说明文档了，这里以流量整形模块的协议参数配置文件“pacer.txt”为例，该内容如下：

[timestamp:0]pacer_mode:originpacer_config:burst_tokens=10,max_pacing_rate=1000

“pacer.txt”文件使用 UTF-8 编码，三行，顺序固定，行首和行尾不要留空白，其中第一行[timestamp:编号]中的编号与所在子目录名一致，并与第几次文件下载对应，该协议参数配置文件在子目录2中的话，就必须写成 [timestamp:2]。而第二行代表要使用的流量整形模块其名称值，第三行则是具体流量整形模块的参数配置值，第二行和第三行中的内容规范一般由相应API使用说明文档进行说明。

这里仅以流量整形模块的协议参数配置进行示例，而其他模块的协议参数配置需见具体的赛题和相应使用说明文档会进行进一步详细说明。

【注：参赛者不要随便改变提交目录（question目录）的名称、目录结构以及目录路径位置，否则本地实验将无法正常运行】

2.5 本地发送客户端（local_send_client）

当参赛者在本地对所构建的协议参数配置进行评估后，并且对评估的结果非常满意的话，那么下一步就可以将自己构建的协议参数配置发送到远程服务端的测评系统上进行统一评估了，即把提交目录（question目录）及该目录里面的协议参数配置文件通过本地发送客户端打包发送给远程服务端，而该团队竞赛的最终结果（评分）将由远程服务端来进行统一测评。此外，各团队并不是只有一次提交机会，而是有多次提交机会去进行刷榜的（但每天会有提交次数的限额的，具体的限额数量参见竞赛细则等文件），该程序的具体使用方法/命令如下：

./local_send_client  --token xxxxxxxxxxxxxxxx（16位GUID值）

--token命令参数指示参赛团队的唯一GUID值，用于识别此次提交是那个团队的。需注意，团队的GUID不可泄露给他人，请做好保密工作。

因此，每次成功发送后，参赛者可以直接保存这些压缩包文件，做为一种历史提交的记录进行保存，以方便去回溯。

需注意：每个团队的每天提交次数是有限额的，当达到限额次数后，还继续多次进行提交（如超过当天限额后，还继续提交三次），可能会导致账号被封禁，从而让该团队日后都无法进行赛题的提交了，此时，就需要团队去联系管理员去进行账号的解封。

2.6 总结

各位参赛者开始实验的步骤简要过程如下：

阅读相关的API使用说明文档，构建相应的协议参数配置文件，将其放入到提交目录（question目录）以及其子目录中。

运行格式检查程序，以对提交目录（question目录）的目录结构、所存放的协议参数配置文件其内容的格式规范进行检查，以判明所构建的协议参数配置是否合法，是否可以被仿真评估程序所使用。

运行仿真实验评估程序，以对所构建的协议参数配置【提交目录（question目录）】进行网络性能评估，评估各协议参数配置在文件下载场景中的性能。

如果对本地的评估结果比较满意，那么就可以运行本地发送客户端将所构建的协议参数配置【提交目录（question目录）】发往远程服务端的测评系统上进行统一评估与计分。
