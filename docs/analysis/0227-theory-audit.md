# 0227 任务理论审计报告：QUIC 流控窗口与连接级流控动态博弈分析

## 1. 理论背景与 QUIC 双层流控机制
QUIC 规范（RFC 9000）定义了双层流控信用额度（Credit-based Flow Control）：
1. **流级流控 (Stream-level Flow Control)**：通过 `MAX_STREAM_DATA` 帧限制单条流的未确认发送字节数；
2. **连接级流控 (Connection-level Flow Control)**：通过 `MAX_DATA` 帧限制整条 QUIC 连接内所有活跃流的总字节数。

在连续六次大文件传输中，若接收端流控更新帧延迟滞后，发端将面临流控假死（Flow Control Stall），导致发包引擎被强制挂起。

## 2. 仿真参数与动态博弈数据
针对 $2.5\text{MB}$ 单文件流及 $41\text{ pkts/4ms}$（$98.4\text{Mbps}$）高速线速进行滑动窗口更新仿真：
- **连接级初始窗口**: $16\text{ MB}$；
- **流级初始窗口**: $8\text{ MB}$；
- **单步传输量**: $49,200\text{ 字节 / 4ms}$；
- **传输总步数**: 54 步（约 $0.216\text{s}$ 密集注入）；
- **流控窗口挂起次数 (Window Stalls)**: **0 次**；
- **最大窗口占用比例**: **$31.67\%$**（远低于 $< 75\%$ 安全警戒门槛）；
- **零停顿传输认证**: 通过（`zero_stalling_verified: True`）。

## 3. 结论
默认流控配置为 $41\text{ pkts/4ms}$ 突发整形提供了充足的接收缓冲区信用额度，完全杜绝了应用层流控截断对传输速度的负面影响。
