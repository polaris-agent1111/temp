# Task 0265 理论审计报告：官方 6 阶段目录切换原子性极限并发读写压测

## 1. 压测背景与原子性挑战
在 11/08 实弹连发期间，自适应决策引擎（`sequential_adaptive_night.py`）需要根据上一发实际出分在阶段间或发次间动态热更新 `question/1..6/pacer.txt`。
若客户端（如评测守护程序、格式检查器或后台监视器）在写操作发生的同一微秒读取配置文件，可能面临三类严峻风险：
1. **半包/截断读取 (Torn Read)**：读到部分写入的配置，导致行数不足 3 行或语法解析异常；
2. **空文件风险 (Zero-byte Read)**：先清空再写入的非原子写入模式下读到 0 字节；
3. **文件锁冲突 (NTFS Sharing Violation / WinError 5)**：Windows NTFS 在重命名过程中对目标句柄锁定，未加保护的读取或重命名抛出异常。

## 2. 解决方案与原子架构设计
1. **写侧（Writer）**：采用“临时文件写入 + 带退避的原子重命名（Atomic Replace with Exponential Backoff）”机制：
   先在目标同级目录下写入 `pacer.txt.tmp`，随后调用底层 `os.replace`（映射至 Windows 的 `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)`），确保目标文件指针在文件系统目录项中瞬间切换，杜绝任何中间半包或 0 字节暴露。
2. **读侧（Reader）**：加入微秒级瞬态冲突重试包装器（`resilient_read_bytes`），在遇到极小概率的微秒级目录项锁定时自适应退避 0.5ms，实现透明无损读取。
