## 一、veth-pair 数据路径逐跳预算：虚拟化税 = µs 级，且大头与瓶颈并行

| 跳 | 下界 (µs) | 上界 (µs) | 是否消耗瓶颈容量 |
|---|---|---|---|
| QUIC sendmsg → UDP 栈（syscall+校验和） | 1.0 | 3.0 | 否 |
| dev_queue_xmit → qdisc enqueue | 0.5 | 2.0 | **是（~3µs 逐包相加）** |
| qdisc dequeue（tbf/netem 定时器驱动另计精度项） | 0.5 | 5.0 | 是 |
| veth_xmit：sk_buff 复制/转发对端（~1.3KB memcpy） | 1.0 | 3.0 | 否（转发后进对端栈） |
| 对端 netif_rx → NAPI/softirq（空闲/背载） | 2.0 / 0 | 30 / 200 | 否 |
| IP/UDP 解栈 + socket 分发 | 1.0 | 5.0 | 否 |
| **合计** | **6** | **248** | 仅 ~3 µs 串行 |
| **单包串行化 @100Mbps（W=1271B skb 域，0080）** | **101.7** | **101.7** | **是（逐包硬成本）** |

1. **量级分层**：串行化 101.7 µs ≫ 路径串行开销 ~3 µs ≫ 空闲路径延迟 6–40 µs；veth 无真实 TX ring、无 BQL、无硬件中断合并——发包即转发，**不存在物理网卡的 µs 级随机化源**。
2. **对网格的影响**：3 µs/104.7 µs ≈ 2.9% 的瓶颈容量税（已在 0080 天花板 94.41 Mbps 口径内）；对 4ms refill 网格 = 0.075%、对 100µs pacing 网格 = 3%——均低于参数扰动粒度（±1 包 = ±8%）。
3. **GRO/UDP GRO（内核 ≥5.0）**：接收侧合并可把 softirq 成本摊薄，但只影响 µs 级路径延迟，不改变线上字节税（0080 §四 GSO 澄清）。
4. **为什么官方 133s ≈ 本地**（0013）与该结构自洽：官方与本地同为 veth+TC 拓扑时，路径成本同构、无额外固定税——2× 塌方只可能来自定时器粒度（0013 G=4000），不是网卡层。

## 二、瓶颈队列确定性仿真：三种判定的队列级复现

模型：单瓶颈 100 Mbps、drop-tail B=40（0075/0076 缓冲尺度）、服务 = 101.7+3 µs；我方源 = tb 节奏爆发 k/4ms（S1 运行点 k~N(17,3)≈41 Mbps；S2 满需求 k=r）；背景源 = Poisson（seed=42，8s 场景）。

| 场景 | r | 背景 (Mbps) | 丢包率 | qmax | q̄ | p95 (µs) |
|---|---|---|---|---|---|---|
| S1 运行点 | 36/38/40 | 35 | **0.00%** | 22–25 | ~4 | ~1.0–1.0k |
| S1 运行点 | 36/38/40 | 50 | 0.05–0.09% | 40（瞬触） | ~11 | 2.6–2.9k |
| S1 运行点 | 36/38/40 | 59 | 4.8–5.3% | 40（饱和） | ~30 | ~4.1k |
| **S2 满需求 bg=0（隔离检验）** | 36 | 0 | **0.00%**（ρ≈0.94，q̄≈1） | 3 | 1.0 | ~0.2k |
| **S2 满需求 bg=0** | 38 | 0 | **0.00%**（ρ≈0.995 边缘） | 3 | 1.1 | ~0.2k |
| **S2 满需求 bg=0** | 40 | 0 | **4.42%（ρ≈1.05）** | 40（持续饱和） | 38.8 | ~4.1k |
| S2 满需求 | 36/38/40 | 50 | 31–36%（ρ≈1.4） | 40 | ~39 | ~4.1k |

1. **隔离检验（S2/bg=0）直接复现 0080 占空比结论**：r=40/4ms 的满需求（10,000 pps）超瓶颈容量（≈9,551 pps）→ 无背景也持续丢包；r=38 恰在容量边缘；r=36 稳定。**40/38/36 的阶梯不是经验微调，是容量守恒的阶梯**。
2. **运行点自洽**：我方 41 Mbps + 背景 35 Mbps（总 76）零丢包、q̄≈4；+50 Mbps（总 91，ρ≈0.91）爆发峰值瞬触 B=40（0.05–0.09%）——**冠军爆发结构在份额挤压下的安全边界就在背景 50 Mbps 附近**，与 0076 坏相位侵蚀（阈值 18.5–28.5 包背景突发）同量级。
3. **过载演示**：满需求 + 份额挤压 → 31–36% 持续丢包 → CC 必然退避回份额——「名义速率超过物理天花板的部分自动转化为丢包+退避而非净荷」（0075 膝点、0080 §二的队列级演示）。

## 三、TC 子系统计时后端：瓶颈也活在定时器网格上

| shaper | 计时后端 | 粒度 | 与本方结论对接 |
|---|---|---|---|
| tbf | 老内核 jiffies 粗定时器 → 新内核 hrtimer | 4ms / ns | jiffies 后端 → **瓶颈限速锁 4ms 网格**，与我方 refill（0081 §一）同网格 |
| netem | hrtimer + rbtree 延迟出队 | ns | 限速精度足够；排队延迟由延迟出队队列决定，同 §二表 |
| htb | 内部令牌 + 类量子调度（500µs–10ms 量子） | 类量子 | 41 Mbps 份额与 class 量子化行为相关 |
| fq/fq_codel | EDT + hrtimer | ns | pacing 网格由 EDT 决定 |

**核心交叉发现**：若官方瓶颈限速器为 jiffies 后端（tbf/htb 早期实现），则**瓶颈服务节拍与我方 refill 同时锁在 4ms tick 相位**——0081 的相位锁定不仅作用于我方发射，也作用于瓶颈侧；两相位差恒定 → §二的延迟/丢包是确定性周期模式而非随机过程。含义：官方「重复多次取平均」的方差来源部分是**相位稳定性**——稳态时段方差小、相位冲突时段方差放大。这为「平台点 vs 尖点」纪律（邻域稳定要求）提供了机理：参数若落在相位冲突构型，方差会随复测放大。

## 四、对参数与答辩的含义

1. **不要再追 µs 级路径优化**：veth 路径成本对总时长的影响 <0.1%；杠杆在爆发结构（0080 占空比）、速率选择（0075 膝点）与定时器共振（0081 网格）。
2. **r=40 的答辩口径升级**：「满需求突发占空比 100.6–103.6%（三域）+ 队列级仿真 4.42% 无背景丢包——40/4ms 是结构性超容量，38/36 是容量阶梯」。
3. **复测合规论证**：确定性相位模式 → 官方统一复测的可重复性有物理基础（与反过拟合纪律同向：稳定机制不依赖抽样运气）。
4. **B=40 缓冲是瓶颈行为假设**：0075/0076 从丢包模式反推的缓冲尺度，本仿真把它作为给定；若真实 qdisc 为 fq_codel（主动队列管理），行为不同——见 §六。

## 五、结论与合规口径

1. **微延迟解构**：veth+TC 固定路径 6–248 µs、串行分量仅 ~3 µs；串行化 101.7 µs 主导——虚拟化税可忽略（<2% 网格）。
2. **队列级三重复现**：0080 占空比阶梯（S2/bg=0）、运行点安全边界（S1）、过载转化律（S2/bg=50）。
3. **相位交叉**：jiffies 后端瓶颈与 4ms refill 同网格共振；碰撞确定性 → 复测方差可解释。
4. **合规**：全部为公开内核语义 + 本侧确定性仿真（stdlib random，seed=42）；**零远程探测、零环境修改、零提交**；官方容器内核版本/HZ/qdisc 类型/限速器后端均不可观测，已按后端包络呈现。

## 六、风险与未决

- 官方 qdisc 类型未知：drop-tail（B=40）为 0075/0076 反推的给定；若真实为 fq_codel/AQM，§二表的丢包模式会变为 ECN/降队列而非尾丢，膝点结论需重标定。
- 逐跳预算为公开语义+文献锚的量级表，非实测；绝对值 ±2×，但「串行化主导、路径可忽略」的量级分离对 ±2× 不敏感。
- 背景源建模为均匀 Poisson：真实背景流（官方流量模型）有相关结构，S1@50 的 0.05% 瞬触丢包率会随相关性变化；仅作量级演示。
- 本仿真 8s 窗口不代表完整会话；r=38 的 ρ≈0.995 边缘态在更长窗口/更重尾 demand 下的丢包率未收敛（属 S2 隔离检验的定性区）。
