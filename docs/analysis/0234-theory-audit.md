# Task 0234 Theory Audit: 决选树热加载原子切换与飞行校验架构

## 1. 业务背景与性能诉求

在 11/08 决战日的「打一发再分析下一发怎么打」闭环自适应执行器（`tools/sequential_adaptive_1108.py`）中，当收到前一发的官方出分与信道状态判定后，系统需要在极短时间内完成候选树的热加载切换：
- 候选配置：`crown-fusion`、`plateau-a`、`ultra-low`、`bbr-probe`、`defense`；
- 目标路径：`question/1/pacer.txt` 至 `question/6/pacer.txt`。

为杜绝切换过程中的中间态竞争、文件半写入、文件锁冲突或目录覆盖导致的评测客户端读取异常，必须建立**内存预渲染 + 直接覆写 + 飞行哈希校验**的原子流水线。

## 2. 原子热加载机制设计

1. **预渲染内存缓冲区**：在脚本启动时，将 5 大候选配置树的 30 个 `pacer.txt` 文件内容（严格 3 行、LF 换行、无结尾空行、`[timestamp:N]` 对齐）预渲染至内存字典，消除磁盘生成延迟；
2. **就地原子覆写**：直接向既有 `question/{1..6}/pacer.txt` 发起顺序覆写，规避 Windows NTFS 在频繁 `mkdir/rmdir` 下的目录元数据锁等待；
3. **飞行 SHA-256 签名比对**：在写入内存流的同时，流式计算 6 个文件的聚合 SHA-256 哈希值，与预存清单进行比对；若哈希不符或格式校验异常，立即阻断提交，确保上行文件绝对零污染。

## 4. 结论

本工具验证了 1-by-1 动态自适应决策引擎在实战切换时的极高可靠性与亚毫秒级性能，确保在官方出分后的决策窗口内毫无延迟地完成策略部署。
