# Task 0236 Theory Audit: QUIC ACK Frequency 延迟确认阈值优化模型

## 1. 协议背景与反向信道开销微观分解

在经典 QUIC (RFC 9000 §13.2) 机制中，接收端默认遵循延迟确认规则（Delayed ACK），即通常每收到 2 个全尺寸数据包（`N_ack = 2`）或超时 25ms 必须触发一次 ACK 反射：
- 对于 60MB 文件传输（约 50,000 个 1200B 数据包），基线策略产生 $25,000$ 个反向 ACK 数据包；
- 每个 ACK 包包含 IPv4 头（20B）+ UDP 头（8B）+ QUIC 短首部（20B）+ ACK 帧（16B）= 64 字节；
- 累计反向数据量高达 $1,562.5\text{ KB}$。

在评测链路或存在双向竞争背景流时，过密的反向 ACK 不仅占用反向链路带宽，还会触发客户端操作系统内核频繁软中断与网卡 ring buffer 竞争。

## 2. ACK Frequency 扩展帧优化机理

通过 QUIC `ACK_FREQUENCY` 帧协议扩展，发送端可动态协商反向确认参数：
1. **确认包阈值 $N_{\text{ack}}$ 提升至 5 包**：由于我方发送端以 37.5 pkts/4ms 的高线速发送，5 个数据包仅需 $0.533\text{ ms}$ 即可累积完成，完全在 $4\text{ ms}$ 漏桶时间槽内；
2. **最大确认延迟 $T_{\text{ack\_delay}} = 4.0\text{ ms}$**；
3. **Pacing 解耦特性**：我方采用精确用户态漏桶 Pacing 发送，数据包发射由高精度微秒定时器主动驱动，而非依赖 ACK 到达触发的「ACK Clocking」；因此 ACK 频率降低对前向发送时隙的额外延迟增加严格为 $0.000\text{ ms}$。

## 4. 结论

ACK Frequency 阈值优化显著减轻了反向信道负荷与接收端处理中断开销，且完全不影响皇冠融合算法前向漏桶的精准出包节奏。
