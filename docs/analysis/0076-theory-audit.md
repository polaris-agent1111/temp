## 一、噪声底清单（与 pacing 网格 τ_p=100 µs @96M 对照）

| 噪声源 | 周期/量级 | 作用点 |
|---|---|---|
| TSC/clocksource 读数 | ~1 ns | **仅记账精度**：credit 时间戳是 ns 网格 |
| hrtimer 事件设备（LAPIC） | ~1 µs | 到期编程精度 |
| timer slack（非 RT） | 50 µs | 唤醒合并 |
| **实测唤醒迟滞（0068）** | **0.8–1.2 ms** | CFS/softirq 唤醒路径——主噪声 |
| jiffy tick（HZ=250） | **4 ms** | 普通定时器路径（0013 的 G=4000µs 锚点） |
| cgroup cpu.max 周期 | 100 ms | CPU 争用时限流（本侧不可验证，仅标记） |

**别名命题**：hrtimer 的「纳秒时钟源」只保证读数与记账精度；发射时刻的实际精度 = 唤醒路径噪声。ns 网格 × ms 唤醒 = 两种确定性机制（见 §二），不是随机白噪声。

## 二、机制分离：schedule 型 vs interval 型（本审计核心）

| | precise_rate_based（schedule 型） | leak_bucket / tb refill（interval 型） |
|---|---|---|
| 迟滞后果 | **速率守恒**，迟滞转为 catch-up 聚簇 | **间隔被拉伸** → 速率折损 |
| MC 结果（96M，Δ∈[0.8,1.2]ms） | eff **96.00 Mbps**，聚簇 10.5–12 包 | eff **76.8 Mbps（80%）** |
| 0068 实测锚 | —（本次给出机理） | 77–87% ✓ 复现 |
| 4ms jiffy 回退 | 聚簇 40.5–42 包（**=缓冲尺度**） | 间隔→8ms，速率 ~48% |

**共振/别名分类**（T_w/τ_p）：1ms=10.00、4ms=40.00、100ms=1000.00 全为整数 → **LOCKED**（确定性聚簇，无 Bresenham 漂移）；50µs slack=0.50 → DRIFT。整数锁定的工程含义：噪声周期与 τ_p 成整数比时，聚簇尺寸恒定、相位可预测——4ms jiffy 回退恰好产出 40 包聚簇，**一台 drop-tail B=40 的交换机缓冲正好被单次聚簇填满**，任何同时刻背景包即丢包。这是「leak_interval_us ≥ 4000 铁律」（0013）在 schedule 型一侧的镜像推论：**jiffy 尺度的迟滞对 96µs pacing 网格是共振放大器，不是白噪声**。

**clock_granularity 的两种读法**（官方语义：预计发送时刻 ≤ now+g 即可发）：
- **惰读**（每包定时器，只放行已到期包）：理想 slack 下聚簇=1（真平滑，4plus2 文档「96µs 均匀打散」在此读法下成立）；迟滞下聚簇=lag/τ_p。
- **贪读**（每次检查放行所有 ≤ now+g 的包）：即使零迟滞也有 g/τ_p≈**10–11 包**聚簇下界。
- 两种读法速率都守恒；真实实现未观测——0051/0060 的 96 ms 恢复常数拟合成功隐含「未发生灾难性持续聚簇」，倾向惰读或中等程度贪读。

## 三、队列级后果：丢包阈值的聚簇侵蚀

稳态（96M，ρ_q=0.96，M/D/1 底噪 E[N_q]=11.52 包）下后台突发 b_bg 在我方聚簇相位 δ 到达，丢包条件（0066 线速串行化理想化，聚簇按瞬时注入压缩——Mininet veth 线速 > 瓶颈，保守方向）：

$$E[N_q]+\underbrace{\max(0,\,n-\delta/\mu_s)}_{\text{聚簇残差}}+b_{bg}>40$$

| 聚簇 n | 相位域 | 坏相位阈值 b_bg | 理想 pacing 阈值 |
|---|---|---|---|
| 1（惰读理想） | — | **28.5 pkt（全相位）** | 28.5 pkt |
| 10.5–12（实测迟滞） | 0…0.96 ms | **18.5 pkt**（−24 KB） | 28.5 pkt |
| ~20（贪读+迟滞） | 0…1.92 ms | 8.5 pkt | 28.5 pkt |
| 40.5（jiffy 回退） | 0…3.84 ms | **负值（必然丢包区）** | 28.5 pkt |

1. **调度噪声把「安全背景突发」的定义缩小了 10 包（24 KB）**：23–34 KB 的背景突增在坏相位从无害变有害——这就是「微突发诱发机制」的定量形式。
2. **与会话级碰撞对接**：6.bin 窗口期望巨流碰撞 0.58 次/场（ρ=1）；20 包聚簇 @1ms 周期的脆弱头部占空比 96%，保守联合上界 ~0.56 事件/场——**上包络**（背景突发体量与相位非独立，实测 valid 场未见丢包主导的耗时膨胀，0068「无超线性样本」佐证实际远低于该界）。
3. **为什么 96M+4% 是对的**（与 0075 闭环）：40 包缓冲 − 11.5 底噪 − 20 聚簇残差 = 8.5 包坏相位余量仍为正；若上探 98M（ρ_q=0.98，底噪 14.8+聚簇同量级）余量被双重侵蚀——0075 的 P_of 自拥塞区与本文的聚簇侵蚀是**同一物理的两种记账**。

## 四、对参数与架构的含义

1. **clock_granularity=1000µs 默认值是承重墙**：惰读下它只是容差；贪读下它直接决定聚簇下界 g/τ_p。降到 500µs → 聚簇减半但唤醒频率翻倍（CPU 代价）；升到 2000µs → 21 包聚簇逼近缓冲。**维持默认 1000µs**。
2. **precise 与 leak 的互补性有了机理基础**：leak 平滑（固定泄放节奏）但速率折损 13–23%；precise 速率守恒但依赖唤醒路径质量。0068 的模块族对比（leak 长文件 +3–3.7 pp）本质是「折损可控 vs 聚簇可控」的权衡，两者都把 96M+余量作为共同的安全域。
3. **enable_n_in_flight=1 的第二条价值**：旁路在管道清空时立即放行，等价于把「唤醒迟滞造成的管道饥饿」钳制在 1 个 RTT 内——它修的不是速率而是慢启动期与恢复期的管道占空比（与 0074 的启动税结论互补）。
4. **不可验证项的诚实声明**：官方容器的 HZ、NO_HZ 配置、cgroup cpu.max、pacer 线程调度策略均不可从本侧观测；本审计把 4ms（G=4000 锚点反推）与 0.8–1.2ms（0068 实测校准）作为已锚定输入，其余只作机制枚举。

## 五、结论与口径

1. **别名结构**：ns 记账 × ms 唤醒 → schedule 型「速率守恒、抖动聚簇化」+ interval 型「平滑、速率折损」二分；jiffy 4ms 与 τ_p 的整数共振是缓冲尺度风险，亚 G 间隔铁律因此对两类模块统一成立。
2. **定量侵蚀**：实测迟滞档（10–12 包聚簇）把背景丢包阈值从 28.5 侵蚀到 18.5 包（−24 KB）；贪读下界另有 g/τ_p≈10 包；jiffy 回退档必然丢包。
3. **96M+4% + g=1000µs 默认 + n_in_flight=1 的组合**在队列级自洽：底噪 11.5 + 聚簇 20 + 典型背景头部 < 40，与 0075 膝点、0072 方差稳健、0066 平坦区四份独立审计同向。
4. **合规口径**：全部为解析推导 + 确定性 MC（stdlib random，固定种子）；无远程探测、无环境修改；对官方实现的两种读法并行呈现，不做单边断言。

## 六、风险与未决

- 官方 pacer 的贪读/惰读实现未知：聚簇下界（10–11 包，贪读）与主估计（10–12 包，惰读+实测迟滞）恰好同量级，结论对读法不敏感，但绝对侵蚀量 ±10 包。
- 唤醒迟滞 0.8–1.2 ms 来自 leak 4000µs 周期的间接反推（0068），非直接测量；若真实迟滞更小，侵蚀按比例缩小（阈值向 28.5 回升）。
- cgroup 限流场景（1000 包 catch-up）只做了机制枚举，未纳入任何结论；若官方容器存在 CPU 争用时段，它是未被 0065 σ 分解覆盖的潜在方差源。
- E 节联合上界 0.56 事件/场过松（背景体量与相位非独立）；如需收敛应做包级背景流仿真（超出本任务授权范围，未执行）。
