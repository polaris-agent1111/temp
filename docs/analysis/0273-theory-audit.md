# Task 0273 理论审计报告：极端偶发客户端本地持久化断点恢复幂等性验证

## 1. 容灾背景与幂等性要求
在 11/08 跨夜实弹提交中，自动化自适应决策引擎（`sequential_adaptive_night.py`）需跨越数小时连续执行 5 发序列化出击。
在长周期执行过程中，面临不可预知的外部扰动：
- 评测机临时断网、TCP 强制 RESET 或服务端连接瞬断；
- 操作系统 OOM Killer、维护性断电或人为运维终端断连。

竞赛规则明确规定：“每日提交不得超过 5 次，超限可能导致账号封禁；只要连上服务端并识别到团队也会计数”。
因此，**断点恢复机制必须满足绝对幂等性（Strict Idempotence）**：
无论在发包前、发包中、轮询分数的任何微秒发生中断，重启进程后绝不能出现“重发上一发”导致的额度被多扣违规，也绝不能“丢失已出分记录”导致决策树降级。

## 2. 状态机与持久化架构设计
1. **写写隔离原子替换（Atomic State Persistence）**：
   状态写入先写入内存，序列化至 `state.json.tmp`，随后通过原子文件系统调用 `replace()` 覆盖 `state.json`，杜绝文件损坏（Torn Write）；
2. **三态事务记录（Three-State Transaction Protocol）**：
   - 状态 1: `PREPARING_SHOT_k`（本地生成配置树，未发起网络连接）；
   - 状态 2: `SUBMITTED_WAITING_SCORE_k`（已连上服务端并取得网络确认，进入榜单轮询，已绑定 shot_index=k）；
   - 状态 3: `SCORED_SHOT_k`（成功取得真实分数并分析完毕）。
   恢复逻辑：若状态处于状态 2，引擎直接恢复轮询或接入超时安全熔断，绝不重复调用 `./local_send_client`。
