### 1.4 关键新事实：本地 leak 全族都在「非绑定区」

leak 标称速率 = leak_rate/leak_interval：9/1000µs ≈ **105 Mbps**，6/1000 ≈ 70，8/1000 ≈ 92，10/1000 ≈ 116，12/1000 ≈ 138——**全部 ≫ 本地实测有效份额 ~41 Mbps（630 MB / 123.81 s）**。即：

- **本地整场 leak 参数扫描（e3–e9 共 20+ 个点）全部处于整形器不生效区**，族间 114–159 的差异与单配置 std（7–12 s）同量级 → **本地「leak9 最优」大概率是噪声过拟合**（待 0012 统计确认）。
- 本地无法观测 leak 的定时器行为：整形器根本没咬合，测的全是 CC + 背景随机。
- **官方 ×2 的本质**：一旦官方定时器退化使标称速率 ÷4 → 9/1000µs 掉到 ~26 Mbps，**跌破 41 Mbps 份额 → 整形器从「不生效」翻转为「咬合」**，总时长由 CC 份额决定变为由漏桶决定 → 直接进 200 s 量级。

## 2. 差分维度清单（按更新后的证据重新定级）

### 2.1 硬件/并发 → **已排除（主版本）**

同窗他队 129–131 正常、本地 hog 仅 +11%。残差见 H5（他队本地成绩未知的隐含假设）与 H4（按队分流的 worker 差异——这不属于「全局环境慢」，单列）。

### 2.2 评测脚本差异（版本 / 3 次取平均）

- 官方 = 3 次取平均；本地 = 单次。口径差不产生 ×2，但若**官方 leak 实现本身不同**（见 H2），则 3 次平均只是把确定性缺陷稳定地平均出来（v1/v1b 差 0.8% 支持「每次的 3 次都稳」）。
- 本地复现包与官方程序是否同版本：**从未验证**。差异点清单（全部待验证）：
  1. **定时器后端**：官方容器内核 HZ（250 → 4 ms tick）/ `CLOCK_MONOTONIC_COARSE` vs 本地高精度时钟；
  2. **cgroup CPU 配额**：官方评测进程被限流 → 定时线程饿死（与全局并发不同，是「我们的评测进程被配额卡」）；
  3. **leak_bucket 实现细节**：官方按 tick 批量漏出、单位是字节还是包、`bucket_cap` 语义、有无未文档化的旁路；
  4. **默认值差异**：官方构建的 `enable_n_in_flight` 默认、`clock_granularity` 默认。

### 2.3 配置生效差异（tar / timestamp / 路径）

- 支持：format_check 历史上有 CRLF「假成功」前科（本地 80.18 s 类）；tar 顶层目录名含空格（`2026-01-05 13:25:17`）是奇怪设计。
- **反对（新逻辑，较强）**：若配置**没生效** → 官方跑 origin 默认 → 环境健康前提下应 ≈ 本地默认 170 s（167.66/172.33），而实测 245.995 > 170 → **「未生效」解释不了「比默认还慢」**。除非「未生效 + 某种慢」的组合。→ 该维度降级为低概率（H3），但打包链路仍要在 S3 失败时复查（见 §4 Plan C）。

### 2.4 定时器敏感性（主维度，定量展开）

**为什么只有 leak_bucket 中招**（对照五模块，逐个看官方定时器退化 4× 的影响）：

| 模标称 | 标称速率 | ÷4 后 | 与 41 Mbps 份额比 | 旁路机制 | 官方退化下的结局 |
|---|---|---|---|---|---|
| **leak_bucket**（我方 v1） | 105 Mbps | **26 Mbps** | **跌破 → 咬合** | **无**（五模块唯一没有 `enable_n_in_flight`，文档参数表亦无） | **中招**：限速咬合 + 9 包/4 ms 微突发丢包 → CC 退避 → 245 s |
| token_bucket（S3） | 232 Mbps | 58 Mbps | 仍高于 → 不咬合 | 有（默认开）+ 桶缓存吸收空档 | **免疫**（标称余量 ÷4 后仍够） |
| origin（默认） | 不限速（rate=0） | — | — | 机制3 无在途直接放行 | 免疫（无速率级定时器） |
| coarse/precise @12.5e6 | 100 Mbps | 25 Mbps | **跌破 → 咬合** | 有旁路但只救「队列排空」时刻，救不了稳态 | **同样会中招**（预测：rate=线速的 rate-based 配置官方也会腰斩——可作为反向验证） |

**定量核对（标注：近似，待验证）**：官方 245.995 s → 均速 20.55 Mbps。leak 事件 = 9 包 × 1460 B × 8 = 105,120 bit/事件 → 需等效事件间隔 ≈ **5.1 ms**（名义 1 ms 的 ~5 倍）。纯 HZ=250（4 ms 栅格）给出 26.3 Mbps → 纯传输 192 s + 每文件固定开销 ~5 s ≈ 197 s，**比 246 还差 ~25%**；补上「9 包/4 ms 微突发 → 队列溢出 → 丢包 → CC 退避」的二次折扣即可落进 240–250 s（待验证：官方日志拿不到，只能靠 S3/后续实验间接验证）。**结论：4–6 ms 等效间隔与 jiffies 级退化同量级，模型自洽但非精确证明。**
