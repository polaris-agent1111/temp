# 过拟合、测量口径与选型纪律

> 适用范围：所有本地实验、提交计划、技术报告与答辩材料。
> 触发背景：官方「题目测评方式」明确「重复多次取平均」、top 提交统一复测，并把硬编码答案、探测/攻击测评系统、利用评测漏洞列为取消成绩项。

## 1. 官方口径

官方测评流程：

1. 启动虚拟网络仿真环境；
2. 加载背景流量脚本；
3. 读取参赛者提交的参数配置；
4. 参数注入 QUIC 协议库；
5. 执行「多文件连续下载」任务；
6. 记录各文件下载总和时间；
7. **重复多次取平均，更新排行榜**。

评分标准以总传输时间为主指标，稳定性（多次运行结果方差）、鲁棒性、创新性、可解释性、可复现性为辅助指标。公平性条款明确：**排行榜 top 提交将统一复测，防止针对特定随机种子的过拟合。**

这意味着两件事：

- 官方看的是**多次运行的均值**，不是某一次的最好成绩；
- 针对某一次随机背景流调出来的「尖点」配置，会在复测中暴露。

## 2. 当前数据说明了什么

以 `test-hybrid-tb4-p100M-p96M` 为例：

| 指标 | 数值 |
|---|---:|
| 样本数 n | 3 |
| 最小 | 116.542s |
| 均值 | 137.430s |
| 最大 | 151.371s |
| 标准差 | 18.42s |
| 变异系数 CV | 13.4% |
| 标准误 SE | 10.63s |
| 均值 95% CI（t 分布） | 约 [91.7, 183.2]s |

现役锚点 `leak 36/40/4000`：

| 指标 | 数值 |
|---|---:|
| 样本数 n | 12 |
| 本地均值 | 132.71s |
| 标准差 | 10.11s |
| 标准误 SE | 2.92s |
| 均值 95% CI | 约 [126.3, 139.1]s |
| 官方实测 | 133.086s |

两件事很清楚：

1. **116.542s 是 n=3 的最小值，不是期望值。** 同一构型的均值是 137.430s。按官方「多次取平均」的口径，用 116.5s 去对比官方 133.086s 是口径错误。
2. **统计上无法区分冠军构型和锚点。** 均值差约 4.72s，Welch 标准误约 11.02s，t≈0.43，p≈0.7；n=3 的区间极宽。当前数据不足以支持「冠军构型显著优于锚点」。

分文件也呈现同样的问题：

| 分段 | 最小 | 均值 | 最小比均值低 |
|---|---:|---:|---:|
| 1–4.bin | 23.98s | 26.66s | 10.1% |
| 5.bin | 31.03s | 37.00s | 16.1% |
| 6.bin | 61.53s | 73.77s | 16.7% |

「111.447s 信封极限」是 `23.279 + 30.134 + 58.034`，三项分别来自不同构型的不同单场最小值。它是**跨构型的理论下界**，不是任何一次实验可达的预期成绩，不能直接写成冲冠目标。

## 3. 为什么 min-of-N 不可取

- **选择偏差**：从同一分布里多抽几次，最小值必然低于均值。用它做预期，相当于把运气当成能力。
- **与官方复测冲突**：官方 top 提交会复测；针对某次背景流抽出的低分，在换种子后会回落到均值附近。
- **与稳定性辅助指标冲突**：高方差本身就是扣分项。冠军构型 CV≈13.4%，不是稳定平台点。
- **与自己的纪律冲突**：仓库内已有「禁止针对固定种子的尖点配置」「只投平台点（n≥3、CV 小）」的规定；min-of-N 与之直接矛盾。

## 4. 选型门槛

### 4.1 候选阶段

- 至少 n≥3；不足 3 次的配置只能记为「探索点」，不得进入主推。
- 同时报告 min、mean、median、std、CV、95% CI。
- 必须过滤 `valid=false`（六文件失败/假成功）和 `load-*`（CPU 争抢污染）样本。
- 参数邻域做 ±1 包或 ±1 单位扰动；邻域内性能不应显著变差。

### 4.2 主推阶段

- 至少 n≥8–10；均值相对现役锚点有明确优势（建议 >3s，且超过合并标准误的量级）。
- CV 建议 ≤5%；若 CV 偏高，先补样本或换更稳定的参数，不要靠 min 冲榜。
- 至少有一个邻域扰动点仍然优于锚点，证明不是孤立尖点。
- 本地与官方分开记录：`local_best`、`local_mean`、`official_score` 三个字段不得混用。

### 4.3 报告语言

| 不推荐 | 推荐 |
|---|---|
| 「本地 116.5s，超过全国第一」 | 「本地单场最好 116.5s；n=3 均值 137.4s，尚不能支持超过锚点」 |
| 「冲冠目标 114–116.5s」 | 「待 n≥8 复核均值后，再给出官方预期区间」 |
| 「min-of-N 吃极值红利」 | 「重复实验用于估计方差，选均值稳定的平台点」 |
| 「不存在尖点过拟合」 | 「当前 n=3、CV 13.4%，尚不能排除尖点过拟合」 |

## 6. 提交前检查

```bash
# 1. 统计前先清洗 valid/load 样本
python tools/summarize_hybrid_stats.py

# 2. 审计计划：n、CV、min/mean 差距、过拟合话术
python tools/audit_plan.py --plan runs/submit_plan_1107_wave2_bypass.json

# 3. 配置格式
python tools/validate_pacer.py --selftest
```

`tools/audit_plan.py` 的退出码：0=无风险，1=有风险，2=输入错误。出现以下标记时先修正：

- `NO_LOCAL_SAMPLE`：计划里的配置没有本地样本；
- `LOW_N`：样本数低于门槛；
- `HIGH_CV`：方差过大；
- `MIN_FAR_BELOW_MEAN`：最小值远低于均值，疑似尖点；
- `OVERFITTING_LANGUAGE`：note 中出现 min-of-N、极值红利、破纪录等话术。

## 7. 结论

过拟合不是「多跑几次取最好」的技巧问题，而是**测量口径错误**：官方按均值计分并复测 top 提交，本地按最小值选型会把运气当成能力。修复方向只有一个：**补样本、看均值、看方差、看邻域稳定性，不用 min 冲榜。**
