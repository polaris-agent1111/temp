# Task 0247 Theory Audit: 决选应急排障与备用节点故障转移机制

## 1. 高可用容灾架构与故障模型

在 11/08 决胜战役中，官方单日 5 发提交额度弥足珍贵。若在提交或等待出分期间遭遇客户端崩溃、宿主机网络黑洞或操作系统套接字锁死等单点故障，系统必须能够在不损失状态、不造成重复提交（违反每日最多 5 次红线）的前提下，实现毫秒级快速冷启动与断点续跑。

故障模型分级定义：
1. **P0 致命级（主机失联）**：备用云节点/本地执行机在 15 秒内接管；
2. **P1 严重级（进程死锁）**：调度器守护超时检测在 60 秒内触发 kill 与套接字重置；
3. **P2 告警级（出分延迟）**：出分轮询超 60 分钟触发 fallback 降级。

## 2. 三步原子故障转移流水线

1. **状态快照无损校验**：
   - 备用节点启动后，首要任务是只读读取 `runs/adaptive_night_state.json` 与 `runs/submissions.jsonl`；
   - 严格确认已发送成功的批次与当前等待状态，从根源上杜绝重复提交风险；
2. **配置指纹哈希核验**：
   - 调用 `tools/validate_pacer.py` 与 `audit0244_config_fingerprint.py`；
   - 验证配置树 30 个 `pacer.txt` 文件与预设 SHA-256 复合指纹逐位一致，杜绝脏文件污染；
3. **自适应流水线状态无缝续接**：
   - 携带 `--resume` 参数启动自适应调度器，精准跳过已执行批次，从断点直接进入下一轮决策。
