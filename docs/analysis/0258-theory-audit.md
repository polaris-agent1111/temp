# 0258 任务理论审计：零拷贝数据包发送路径与内核环形缓冲区溢出防御

> 任务单：`zcode/requests/0258`（2026-11-07）。脚本：`zcode/scripts/ringbuf0258_zero_loss.py`；原始输出：`zcode/scripts/_0258_out.md`。
> 承接口径：0249（1200 B = IP 满包裁决；r=40 全口径安全上界、r=41 口径敏感）、0085（tb 停顿倾泻 60 包机制、B=40 交换机队列）、0082/0083（100 Mbps 接入/汇聚）。
> 合规声明：纯本地 numpy 闭门数值实验，零网络、零提交、零受保护路径写入。流量整形模块运行在平台侧（固定实现，参数经 pacer.txt 提交）——本审计是发送路径安全性的防御性确认与答辩材料，非可执行优化杠杆。

## 1. 90 Mbps 线速微积分与稳定性下界

| 量 | 值 | 出处/推导 |
|---|---|---|
| 包率 @90 Mbps | **9375 pkt/s** | 90e6 / 8 / 1200 B（convention A） |
| G=4ms tick 配额 | 37.5 pkt/tick | 0248 timer-granularity 口径 |
| 理想等间隔 T_e | 106.67 µs | 1/9375 |
| NIC DMA 排空速率 | **10417 pkt/s**（96 µs/包） | 100 Mbps 接入链路线速 |
| 净排空盈余 | **+1042 pkt/s** | 排空 − 入队 |

**核心下界（D/D 确定性）**：入队 9375 < 排空 10417 ⟹ 稳态环占用无积累，**backlog 上界 = 最大瞬时批量**。零丢包条件归结为单条不等式：

$$N_{\text{ring}} \ge \max_{\text{机制}}\ \text{瞬时批量} + 1 \quad (\text{+DMA 在途余量})$$

## 2. 各 pacer 机制的临界环深 N\*

| 发射机制 | 瞬时批量 | 临界环深 N\* | N=256 占用率 | 判定 |
|---|---|---|---|---|
| leak 单包等间隔（冠军构型） | 1 | 2 | 0.4% | 安全 |
| tb r40 正常 refill | 40 / 4ms | 41 | 16.0% | 安全 |
| tb 停顿倾泻（单次，0085 S4/5 机制） | 60 | **61** | 23.8% | 安全 |
| 连续 2 次 60 倾泻 | 78 | 79 | 30.9% | 安全 |
| 连续 3 次 60 倾泻 | 97 | 98 | 37.9% | 安全 |

连续倾泻链闭式：第 m 次倾泻峰值 = 60 + 18.33×(m−1)（18.33 = 4ms 内排空 41.67 包的残差）；m=1→60、m=2→78.3、m=3→96.7、m=4→115。**默认环深 ≥256 覆盖 m≤10 的病态连续倾泻链**。

## 3. 时钟停摆生存时间（溢出防御的第二道界）

DMA/中断停摆期间环以 9375 pkt/s 继续入队，生存时间 τ = N / 9375：

| 环深 N | 环独立生存 | +qdisc（txqueuelen 1000）联合 |
|---|---|---|
| 64 | 6.8 ms | 113.5 ms |
| 128 | 13.7 ms | 120.3 ms |
| **256** | **27.3 ms** | **134.0 ms** |
| 1024 | 109.2 ms | 215.9 ms |

现代 NIC 中断合并 <1 ms、PCIe 停摆亚毫秒级 —— **N=256 下停摆威胁有两个数量级裕量**。

## 4. 蒙特卡洛验证（确定性排空 96 µs/包，300 s × 5 种子）

| 场景 | 机制 | 最大环占用 | N=64 丢包 | N=128 | N=256 | N=1024 |
|---|---|---|---|---|---|---|
| ideal-90M | 等间隔 106.7 µs | 1.0 | 0 | 0 | 0 | 0 |
| jitter-37 | 间隔 ×U[0.7,1.3]（88.8 Mbps） | 3.0 | 0 | 0 | 0 | 0 |
| jitter-38 | 间隔 ×U[0.7,1.3]（91.2 Mbps） | 3.8 | 0 | 0 | 0 | 0 |
| tb-r40-refill | 40 批量/4ms | 40.0 | 0 | 0 | 0 | 0 |
| tb-dump60 ×1/×2/×3 | 连续 m 次 60 倾泻 | 60/79/97 | 0 | 0 | 0 | 0 |
| **runaway-41B（负面对照）** | 41/4ms，1228 B 排空 98.24 µs | 持续增长（2.1 万+ @300s） | **306 万** | 306 万 | 304 万 | 293 万 |

- **抖动免疫**：净负漂移随机游走（均值间隔 105–108 µs > 96 µs 排空）下 300 s 峰值占用仅 3–4 包——速率抖动不构成环溢出威胁。
- **负面对照（已否决构型的独立佐证）**：r=41 在 convention B（线材 1228 B）下入队 10250 pkt/s > 排空 10179 pkt/s，净积累 71 pkt/s → **N=1024 环 14.5 s 填满、+qdisc 28.6 s 起持续丢包**。这是 0249「r=41 口径敏感、r=40 全口径安全」裁决在内核发送路径上的独立复现——r=41 的风险不仅在交换机浅队列，也在本机环缓冲。
- **判定**：全部现实场景在 N=64 即零丢包；但单次 60 倾泻 N\*=61 使 N=64 处于 95% 占用临界边缘 → **工程判定零丢包下界取 N≥128；主流默认 N≥256 时裕量 4.2 倍。「90Mbps 线速下 ring buffer 零丢包」PASS**。

## 5. 零拷贝发送路径的 CPU 微积分

| 路径 | 每包成本 | 单核占用 @9375 pkt/s | 说明 |
|---|---|---|---|
| 内核态拷贝（1200 B memcpy @~12 GB/s） | ~100 ns | 0.094% | MSG_ZEROCOPY 可省，但补完成队列通知成本相当 |
| sendto 系统调用（协议栈 + skb 分配） | ~1.5 µs | 1.40% | 主要开销项 |
| sendmmsg 按 G-tick 批量（37.5 包/次） | ~40 ns 摊销 | 0.037% | **省 ~1.36 个百分点，真正有效的路径优化** |

- 零拷贝的设计目标在 >1 Mpkt/s 量级；9375 pkt/s 下其收益 ~0.1% 单核——**90 Mbps 线速下零拷贝非必需**。
- 环形缓冲区零丢包的主保障是「节奏入队 ≪ 排空速率 + 默认环深 ≥256」，与发送路径拷贝策略无关；即「零拷贝 vs 拷贝」在本题速率下是伪命题，批量系统调用才是有意义的杠杆（且平台侧固定，仅作答辩材料）。

## 6. 溢出防御条件总表（答辩用）

| 威胁 | 触发条件 | 量化界 | 现状裕量 |
|---|---|---|---|
| 瞬时批量超环深 | burst > N | N\*=61（60 倾泻） | 默认 256：4.2× |
| 连续倾泻链 | m 次 60 倾泻 | 峰值 60+18.33(m−1) | m≤10 安全 |
| DMA/中断停摆 | 停摆 τ > N/9375 | 27.3 ms（N=256） | ~2 个数量级 |
| 持续超线速 | 入队 > 排空 | 仅 r=41-B 口径（+71 pkt/s） | 已被 r=40 裁决排除 |
| qdisc 溢出 | backlog > 1000 | 与环联合 134 ms 停摆裕量 | 充分 |

## 7. 结论

1. **90 Mbps 线速下内核 TX ring 零丢包：PASS**——D/D 下界（backlog ≤ 瞬时批量）+ MC 七场景五种子 ×300s 双重验证；工程下界 N≥128，默认 N≥256 裕量 4.2 倍。
2. 唯一溢出场景是已否决的 r=41-convention-B：净积累 71 pkt/s，14.5 s 填满 N=1024 环——**为「绝不投 r=41」提供内核侧第二证明**。
3. 零拷贝在 9375 pkt/s 下收益 ~0.1% 单核、非必需；批量 sendmmsg 收益 ~1.36%，同为平台侧固定实现的答辩材料。
4. 局限：DMA 排空按 100 Mbps 线速确定性建模（真实 NIC 有中断合并抖动，方向上只会增加环占用 ~µs 级、不改变结论）；环深 N 的平台实际值不可观测（256/1024 为 mininet/Containernet veth 与主流 NIC 默认量级，结论按 N 表格给出，覆盖任意实际取值）。
