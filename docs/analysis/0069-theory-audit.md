# 0069 — BBRv1 拥塞控制在 Mininet 容器下的 BtlBw 与 RTprop 滤波动力学建模

> 撰写：zcode ｜ 2026-11-07 04:05 ｜ 仿真脚本：`zcode/scripts/0069_bbr_dynamics.py`（轮级流体模型，纯标准库）
> 口径依据：《六载穿柜》拓扑（业务路径单向 35 ms / RTT 70 ms；接入与汇聚均 100 Mbps）、单包 1200 B
> → μ_s = 10.42 pkt/ms、BDP = 729 包；Q_lim = 100 包（实测弹性界 B*=60 + 背景占用 ~40 校准，见 0066/0070）；
> 官方容器定时器量化 G = 4000 µs。
> **适用性声明**：平台未公开服务端 QUIC 实现的 CC 算法。本审计给出「若 CC = BBRv1」的条件模型与
> 可观测判据；所有结论均以该条件为前提。

## 1. BBRv1 滤波器形式化

### 1.1 两个核心估计器

**BtlBw（瓶颈带宽）= 10 轮最大值滤波**：

$$\widehat{B}(k) = \max_{j \in [k-9,\,k]}\; \mathrm{DR}_j,\qquad \mathrm{DR}_j = \frac{\text{deliver}_{j}}{T_j}$$

其中 delivery-rate 样本 DR 按轮（RTT 粒度）计算；窗口按轮数过期，10 轮 ≈ 0.7 s（RTT=70 ms）。

**RTprop（最小 RTT）= 10 s 窗口最小值滤波**：

$$\widehat{R}(t) = \min_{\tau \in [t-10\text{s},\,t]}\; \mathrm{RTT}(\tau),\qquad \mathrm{RTT}(\tau) = RTT_{prop} + q(\tau)/\mu_s$$

app-limited 样本不计入；min 滤波对加性噪声不敏感（下侧包络保持），但**只能被更低值刷新**。

### 1.2 控制律（模型中使用）

| 相位 | pacing gain | cwnd gain | 退出条件 |
|---|---|---|---|
| STARTUP | 2/ln2 ≈ 2.885 | 2/ln2 | 连续 3 轮 delivery 增速 < 25% |
| DRAIN | ln2/2 ≈ 0.347 | — | inflight ≤ BDP_est（或 ≤3 轮） |
| PROBE_BW | 循环 [1.25, 1×6, 0.75] | 2 | 每 8 轮循环 |
| ProbeRTT | — | cwnd ≤ 4 | ≥ 200 ms |

$$\text{pacing\_rate} = g_p\cdot\widehat{B},\quad \text{cwnd} \ge g_c\cdot \widehat{B}\cdot\widehat{R},\quad \text{BDP\_est} = \widehat{B}\cdot\widehat{R}$$

### 1.3 Mininet 容器映射（本任务的领域特定项）

1. **钳位**：整形模块位于 QUIC CC 之下的服务端 egress——BBR 请求的发送速率被钳到
   $\min(g_p\widehat{B},\,R_{module})$。`origin` 默认无钳位（R=∞）；`precise/leak/token` 系列提供硬钳位。
2. **传播 RTT**：业务路径单向 35 ms → RTT_prop = 70 ms，BDP = 729 包（1200 B 口径）。
3. **定时器量化**：官方容器定时器有效唤醒迟滞 Δt ≈ 0.8–1.2 ms；轮时间测量误差 ≤ G = 4 ms。
4. **浅缓冲**：交换机有效队列上限 Q_lim ≈ 100 包 << BDP（729 包），是后续所有定理的关键约束。

## 2. 六条定理与推导

**T1（BtlBw 上界与锁定）**：样本 $\mathrm{DR}_j \le \min(R_{module},\ (1-\rho_j)\mu_s)$，故
$\widehat{B} \le \min(R_{module},\ \sup_j (1-\rho_j)\mu_s)$。背景持续占 $\rho$ 份额 ≥ 10 轮后窗口内旧峰值
全部过期 → $\widehat{B}$ 锁定在 $\min(R_{module},\ (1-\rho)\mu_s)$（公平份额锁定）。

**T2（STARTUP 倍增收敛与过冲）**：冷启动 pacing 每轮翻倍，从 cwnd₀=32 到 BDP=729 需
$\log_2(729/32)≈4.5$ 轮 = **0.32 s**。退出时 in-flight ≈ 2.885×BDP = 2106 包，过冲 = (2.885−1)×BDP ≈ **1377 包**。
在 Q_lim=100 的浅缓冲上，过冲的 (1377−100) ≈ **1277 包一次性尾丢**不可避免（A1 仿真：轮 5–8 每轮丢
1250–1259 包）。这是 BBRv1 的已知浅缓冲弱点，与 P5 模块族审计中 `origin` 默认档的中位成绩最差（154.84 s）
实测相互印证。

**T3（泵幅恒等式与安全带）**：PROBE_BW 泵相增益 1.25 持续一轮的超额注入

$$\Delta q_{pump} = (1.25-1)\cdot\widehat{B}\cdot\widehat{R} = 0.25\cdot\widehat{B}\cdot\widehat{R}$$

独占链路且 $\widehat{B}=\mu_s$ 时 $\Delta q_{pump} = 0.25×729 = 182$ 包 > Q_lim=100 → **必然自致尾丢**；
安全条件为 $Q_{lim} \ge 0.25\cdot\widehat{B}\cdot\widehat{R} + q_{bg}$，反解得独占链路下安全估计
$\widehat{B} \le (\mu_s + Q_{lim}/RTT)/1.25 = 9.48$ pkt/ms ≈ **91% 线速**。**模块钳位把泵速率改为
$\min(1.25\widehat{B}, R)$**：当 $R \le \mu_s$ 时泵幅被钳位归零，风险退化为「持续超额 $R - (1-\rho)\mu_s$」的
常规排队问题。

**T4（钳位下的稳态方程组）**：钳位且 $R \le (1-\rho)\mu_s$（欠驱）：排放 = R，队列 ≈ 0，RTprop=70 ms，
cwnd 自由 → 全稳态无丢包；$R > (1-\rho)\mu_s$（过驱）：队列每轮净增 $(R-(1-\rho)\mu_s)×70$，至
Q_lim=100 后转为周期性尾丢，期望丢包率 ≈ $\max(0, R/(1-\rho)\mu_s - 1)$ 的量级。B 扫描仿真复现该单调
结构：R=100→19.3%，96→18.9%，85→14.8%，70→9.9%，50→1.9%。

**T5（RTprop 续签/偏置/ProbeRTT 触发定理）**：RTprop 偏置仅当队列在整个 10 s 窗口不排空时发生
（偏置 = q_min/μ_s）；**任何一轮队列排空（RTT 采样到 70 ms）都会续签 min 滤波时间戳**（Linux tcp_bbr
对 min_rtt 采用 ≤ 判据），从而推迟 ProbeRTT。推论：
- websearch 背景含 ~10% 空闲轮 → min 滤波持续自愈 → **ProbeRTT 不触发**（C2：300 轮 0 次），
  长文件稳态不会被 200 ms 塌坑打断；
- 30 MB 巨流窗口（队列常驻 > 10 s）→ 强制 ProbeRTT（C1：21 s 内 3 次），代价 200 ms/10s ≈ **2.0% 窗口
  吞吐**（6.bin 量级摊薄后 ≈0.3%）。

**T6（G 量化偏差）**：轮时间测量 $\hat{T} \in [T-G, T]$（max 滤波取小 T̂ 上偏）→
$\widehat{B}$ 上偏因子 $T/(T-G) = 70/66 = 1.061$（**+6.1%**）。该偏差推高 pacing 与 cwnd 各 6.1%，
在浅缓冲上等价于泵幅裕度收缩 44 包（0.061×729）。RTprop 为 min 滤波，对量化噪声天然免疫。
veth/CPU 调度抖动与 G 量化同向叠加，mininet 容器内该上偏是**结构性**的。

## 4. 与平台实测的交叉验证

1. **origin 默认档最差（P5：中位 154.84 s）** ↔ T2：无钳位 BBRv1 的 STARTUP 过冲 + 泵丢在浅缓冲上
   结构性发生，且 BBRv1 对丢包不降速（T4/A4），损失无法自愈。
2. **6.bin 中位利用率 36.2%（0068 P1）** ↔ T1 公平份额锁定：$\widehat{B}→(1-\rho)\mu_s$，
   pacing 收敛到份额而非 R；36% 中位对应 $\bar\rho ≈ 0.6$ 的重尾长尾段。
3. **非对称构型（1–4.bin 前猛 + 5/6.bin 保守）** ↔ T3/T4：短文件吃 STARTUP 过冲红利（0.32 s 倍增
   到线速的瞬时排水），长文件进入份额锁定稳态——两者要求的速率点不同，单参数无法同时最优。
4. **碰撞敏感（0066 脆弱窗 1.92 ms）** ↔ T3 泵幅恒等式：BBR 泵相的 0.25·BDP 超额与背景巨流叠加时
   是 Q_lim 击穿的第二来源；钳位模块等价于「泵阻尼器」，这是 leak/precise 族长文件更稳（0068 P5
   +3.0–3.7 pp）的 BBR 侧解释。

## 5. 工程含义（在 BBRv1 假设下）

1. **钳位模块 = 泵阻尼器**：R ≤ μ_s 时 PROBE_BW 泵幅归零，BBRv1 的浅缓冲自伤被结构性消除；
   这是对「前 4 文件 leak 40/4ms + 后 2 文件 precise 96M」混合架构的 BBR 侧理论支撑。
2. **R 的安全带上界** = $(1-\bar\rho_{window})\mu_s$，随背景窗口时变：甜点速率不是常数，
   而是「重尾间隙多时可以逼近 96M、巨流窗口必须回落」的状态量——这解释了为何同一配置在不同场次
   出现 36–46% 的利用率散布（0068 H2 的 6.bin 76.4% 集中带）。
3. **ProbeRTT 风险窗口** = 巨流连续占用 > 10 s：30 MB 巨流 @100 Mbps 需 2.4 s 传输，
   单条巨流不触发；只有「背靠背巨流链」才可能造成 10 s 常驻队列 → ProbeRTT 每轮 ~200 ms 塌坑。
   属于小概率但有迹可循的方差源。
4. **G 量化的 6.1% 上偏是结构性的**：在浅缓冲 + 钳位架构下不可消除，应计入安全带裕度
   （与 0066 的 M/D/1 底噪 1.25 ms 并列为不可消除底噪项）。

## 6. fidelity 与局限

- 轮级流体模型，非逐包；delivery 样本语义用 delivered/RTT 近似（真实 BBR 用 send-phase 区间，
  稳态等价、DRAIN 相有半轮偏差）；FIFO 尾丢按我方占比分摊。
- 背景为三态近似（10% 空闲 / 65% 小流 30–55% / 25% 大流 55–95%），ρ̄≈0.49 按 0068 中位份额校准；
  未建模 ACK 频率与 PTO 反应（由 0070 承担）。
- 若真实 CC 为 Cubic/其他，本审计的 T2/T3/T5 不适用，但 T1（钳位即上界）与 T6（量化偏差）仍然成立。
  可观测判据：若 origin 默认档出现「启动后 ~0.3 s 的成串丢包」→ BBRv1 假设得证；若表现为
  「慢启动线性 + 对丢包敏感的锯齿」→ Cubic。
