# 0253 理论审计 — 极端高丢包 5%~10% 环境下 QUIC 发送窗口抗死锁验证

- 日期：2026-11-07 ｜ 执行者：zcode（两个独立脚本互证）｜ 本版为合并版：初稿（18:04，`quic0253_loss_deadlock_defense.py` 确定性单次验证）+ 扩展（18:1x，`ptt0253_quic_pto_liveness.py` 1800-run 分布验证与消融）
- **一句话结论**：**双向独立丢包 p ∈ {5%, 7.5%, 10%}（官方 leak 构型尾损基线 0.157% 的 32~64 倍压力）下，两套独立仿真一致给出 100% 传输完成、全局最小 cwnd = 2（RFC 9002 §7.2 下界）、零死锁、零连接被杀；1800-run 分布验证给出最大无进度 stall 0.22s，较 30s 空闲超时留 136 倍裕度。抗死锁机理 = RFC 9002 §7.5「PTO 探针不受 cwnd 阻塞」+ §6.2.1「退避随 ACK 复位」双条款；消融显示去掉复位条款后 200/200 全灭。须区分「存活」与「有成绩」：p=10% 下 loss-based CC 传 6.bin（320MB）线性外推 ~2618s > 600s 评测界 —— 连接不死但成绩归零，该吞吐型风险与 0086 饥饿结论同源，被官方 0.157% 尾损基线实际排除。**

## 2. 两套独立验证结果

|---|---|---|---|---|---|---|
| reno | 5% / 7.5% / 10% | **100%×3** | 50.9 / 66.7 / 81.8 | **2** | 3 | 0.22 |

## 3. 消融验证：退避复位条款是成败手

若去掉 RFC 9002 §6.2.1 的「任一 ACK 到达即复位退避」（pto_chain 只增不减），PTO 间隔指数翻倍至 10 级（78ms→79.9s）后探针永不触发，reno 200/200 全部在 30s 无进度处被杀（**0% 存活**）；恢复复位条款后同参数 **100% 存活**。**结论：抗死锁 = 「PTO 不受 cwnd 阻塞」（§7.5）与「退避随 ACK 复位」（§6.2.1）两条共同成立，任一缺失即死锁**；也解释了 TCP（RTO 探针受 cwnd 阻塞 + 无 PTO）在同等场景下更脆弱。

## 4. 与 0086 的衔接：存活 ≠ 有成绩

- 0086 已证 loss-based CC 在持续饱和下 cwnd 钉死 CMIN=2，Tier-0 上界 4667s/9333s。本审计给出其随机丢包版本：p=10% 时 reno 传 10MB 需 81.8s（无丢包地板 0.87s 的 94 倍）；按 N 线性外推 6.bin（320MB，六载穿柜 L79）需 ~2618s > 600s 评测界 —— **连接不会死（PTO 活性），但成绩会死（吞吐饥饿）**。
- 对照：bbr 与开环 pacer 上界在 p=10% 下 10MB 仅 1.6s ≈ 地板 × 1/(1−p) + 重传尾 —— **批量=1 的开环漏桶族（冠军构型）对高丢包的吞吐免疫性优于 loss-based 族两个数量级**，与 0085「单包等间隔严格优于批量倾泻」一致。
- 实际工况：官方环境 leak 构型尾损 0.157%（0085），比压力带低 32~64 倍；5%~10% 属裕度认证。

## 5. 局限（如实陈述，两套模型合并声明）

1. 逐 RTT/逐 tick 步进而非逐包事件驱动；对活性判定无影响，完成时间绝对值有 ≤1 RTT 量化误差。
2. 扩展验证丢包 iid，未建模真实阵风的突发相关丢失（0085 批量倾泻一次丢 40~60 包）；相关丢失更伤 dupack 快重传，但 PTO 兜底与 dupack 无关，活性结论不依赖独立性；初稿验证为单向丢包，未压 ACK 丢失面 —— 该缺口由扩展验证补足。
3. ACK 逐包独立不聚合，最坏化假设；真实 QUIC ACK Frequency 会显著降低 ACK 暴露面。
4. RTT=20ms、空闲超时 30s 为声明假设；官方 RTT 更小时 PTO 以粒度项（78ms）为主，结论不变。
5. reno 变体为简化（检测 RTT 减半 + AIMD +1）；CUBIC 会拉高吞吐（0086 已量化），不改变存活结论。
