## 一、问题设定：噪声打在唤醒路径上

继承 0076 的核心判定：ns 级时钟 credit 记账与 ms 级唤醒迟滞之间的「调度别名」意味着 CPU 调度干扰**不打在时钟读数上，打在「计时器到点 → 包真正离开」的唤醒路径上**。本审计把该路径分解为四个 CPU 侧分量，并对官方 leak_bucket（interval 模式）语义量化每一分量的干扰测度。

作用点设定（继承 0085 实测语义）：

| 量 | 值 | 说明 |
|---|---:|---|
| tick 周期 T | 4000µs | G=4000µs，HZ=250 |
| 每 tick 出包数 r | 36 | Shot 2 后程构型（leak 36） |
| 单包间隔 T_e | T/r = 111.1µs | 「严格单包等间隔」语义 |
| 出口单包服务 | 96µs | 100Mbps、1200B 净荷 → 1/96µs |
| 排队安全余量 | T_e − 96 = 15.1µs | 间隔抖动小于它则零排队 |
| clock_granularity g | 1000µs | 官方容差语义；δ>g 触发聚簇-grade 异常 |
| 一次下载 tick 数 | ≈31,000 | T_dl=124s / 4ms |
| 官方单发噪声 σ_d | 7.02s | 0084 分层贝叶斯后验 |

## 二、唤醒延迟 δ 的分量模型（全部为文献量级假设）

$$\delta = \underbrace{\delta_{\text{disp}}}_{\text{回调分发}} + \underbrace{\sum_i c_i}_{\text{上下文切换}} + \underbrace{w_{\text{CFS}}}_{\text{抢占等待}} + \underbrace{m_{\text{mig}}\cdot\mathbb{1}[\text{无亲和}]}_{\text{跨核迁移}}$$

| 分量 | 分布假设 | 量级依据（假设，非实测） |
|---|---|---|
| δ_disp 回调分发 | LogNormal(中位 3µs, σ=0.7) | 内核定时器回调基线 P99≈12µs |
| 上下文切换直接成本 | 窗口内 Poisson(λ_cs)，每次 U(1.2, 3)µs | 寄存器存/恢复经典测量 1.2–3µs |
| 切换间接成本（cache/TLB 污染） | 窗口内 ≥1 次带污染切换的概率 1−e^(−0.3λµs)，Exp(20µs) | 冷 L2/L3 重填 5–50µs 量级 |
| 跨核迁移（无亲和时） | 概率 q_mig，Exp(50µs) | IPI + 冷 L3，20–100µs 量级 |
| CFS 抢占等待 | 概率 ρ 命中，Exp(100µs)；「公平轮转风暴」场景改为 U(0, 24ms) | sched_period×(N_c−1)/N_c 上界 |

λ_cs 场景：空闲 150/s、中载 5000/s、重载 20000/s（每核）。

## 三、蒙特卡洛干扰测度表（seed=42，每场景 31000 tick）

| 场景 | E[δ] µs | P99 δ µs | P(δ>g) ppm/tick | 速率折损 I₁ | ΔT_rate (s) | 队列深 P99 (包) | **ΔT/σ_d** |
|---|---:|---:|---:|---:|---:|---:|---:|
| S0 空闲主机·无亲和 | 11.6 | 193.8 | 0.0 | 0.29% | 0.360 | 0.0 | **0.051** |
| S1 空闲主机·绑核 | 9.1 | 162.9 | 0.0 | 0.23% | 0.282 | 0.0 | **0.040** |
| S2 中载 ρ=0.5·绑核 | 54.4 | 396.6 | 0.0 | 1.36% | 1.687 | 0.0 | **0.240** |
| S3 中载 ρ=0.5·无亲和 | 58.6 | 397.5 | 32.3 | 1.46% | 1.817 | 0.0 | **0.259** |
| S4 重载 ρ=0.9·无亲和 | 101.7 | 467.7 | 96.8 | 2.54% | 3.154 | 0.0 | **0.449** |
| S5 公平轮转风暴(4任务)·绑核 | 10726.3 | 23727.3 | 8.59×10⁵ | 2.68×10³% | 332.5 | 7.0 | **47.4** |

读法：

1. **正常谱系（S0–S4）全部 « σ_d**：即使持续重载（ρ=0.9、2 万次切换/s/核），µs 级 CPU 分量折损全程只有 3.2s（0.45σ_d）；空闲基线只有 0.28–0.36s（0.04σ_d）。这些量级**不足以解释官方-本地差距（0084 口径 μ_B+日漂移≈2.5–7s）或复测方差 σ_d=7s**。
2. **唯一灾难机制是公平轮转风暴（S5）**：多个等权任务长期抢占使 E[δ]=10.7ms 超过 tick 本身，速率折损 27 倍、ΔT≈332s。但该机制要求宿主机长期处于等权 CPU 饥饿——官方拓扑由平台固定，且我方 11-06 已实测「CPU 重载复现官方惩罚失败」（hourly 2026-11-06_0900），说明官方链路不存在该机制。**S5 是被证据排除的机制，仅作为测度上界保留。**
3. **聚簇触发率 I₂ 在正常谱系 ≤97ppm/tick**：即每下载 ≤3 次 δ>1000µs 的聚簇-grade 事件——比 0076 已确立的 clock_granularity 固有聚簇下界（g/τ_p≈10–11 包/聚簇，每 tick 都在发生）低两个数量级，不构成新增风险。
4. **队列深 P99=0（正常谱系）**：间隔抖动 P99 远小于 15.1µs 安全余量，出口不产生微队列，不触发 Drop-tail。

## 四、闭式上界与亲和性净收益

**双 tick 合并的闭式上界**：即使 P(δ>4ms)=10⁻³/tick（每千 tick 丢一次 tick 产出），速率折损恰为 1000ppm → ΔT=0.124s → **ΔT/σ_d=0.018**。这给出一个与任何分布假设无关的稳健结论：leak 模式下 CPU 抖动要吃掉 1σ_d 的成绩，需要 P(δ>4ms)≈5.6%——等价于宿主机过半时间处于 S5 风暴。

**亲和性净收益（S3 对照 S1，同中载参数）**：

| 项 | 数值 |
|---|---:|
| 无亲和 ΔT | 1.822s |
| 绑核 ΔT | 1.684s |
| **净收益** | **0.138s** |
| 迁移项解析值 | q_mig×E[Exp(50µs)]×31000 wakes = 5µs×31000 ≈ 0.155s |

MC 净收益与解析值同量级（0.138 vs 0.155s），交叉验证通过。**绑核收益 ≈0.14s，仅为 σ_d 的 2%**——且这是任务单给不了的动作：官方评测环境的 CPU 亲和性由平台固定，提交侧唯一可控的是 `pacer.txt` 参数。

## 五、三条结构性结论

1. **leak 模式封死了 CPU 抖动的突发通道。** token_bucket 的「停顿积聚 → 一次倾泻至 burst」允许 CPU 迟滞转化为 40–60 包批量（Shot 1/3/4/5 的 140–155s 成绩机理，0085 惩罚律 4.51%/36.34%）；leak 的「严格单包等间隔 + 每 tick 固定放行」使迟滞只能拉长有效周期（速率折损），**不能产生超发批量**（Shot 2 零突发平滑的微观解释）。因此 CPU 干扰测度 I₃（突发通道）在 leak 模式恒为 0——这是构型层面的结构免疫，不是参数调优结果。
2. **µs 级 CPU 分量是已知 ms 级唤醒迟滞的次级项。** 0068 实测 interval 模式唤醒迟滞 0.8–1.2ms（20–30% 速率折损，已被官方配置校准吸收）；本审计分解出的 µs 级分量（空闲 9–12µs）比该迟滞小两个数量级。**即使把 CPU 分量完全归零，官方-本地校准面也不会移动可分辨的距离**（0066 同类判据：效应比 ρ 小 416 倍的量级逻辑）。
3. **与我方既有证伪一致。** 11-06 的 CPU 重载假说证伪 + 本审计的正常谱系上界（≤0.45σ_d）共同指向：官方成绩方差的来源不在宿主机 CPU 调度层，而在 0085 的背景流突发碰撞层（leak36 排空余量 13.6% 被 70ms 阵风穿越的累计丢包 37 pkts 等）。

## 六、对决策的含义

1. **提交侧无 CPU 可行动作**：`pacer.txt` 不含亲和性/优先级/调度类参数；本审计从理论上确认不存在值得申请或探测的环境侧改动。合规红线 1（不得修改评测环境）与该结论自然一致。
2. **选型口径**：继续按 0085 惩罚律 + 漏桶平滑定理选择「零突发」构型（leak 家族），CPU 层面的担忧可以从决策矩阵中移除（对 0094 的输入）。
3. **复测方差预期**：σ_d=7.02s 中可归因于宿主机 CPU 调度的份额 ≤0.45σ_d（重载情形上界）、更可能 ≤0.05σ_d（空闲基线）——**复测波动的主导项必须到背景流随机相位中找**（0083/0085/0086 系列）。

## 七、风险与未决

- **全部 CPU 侧参数为文献量级假设**：官方宿主机的真实 λ_cs、核数、cgroup 配额、内核抢占模式（PREEMPT_NONE/VOLUNTARY）未知。若宿主机实际处于 S2–S4 档，本表的 ΔT 需按对应行读取（仍全部 « σ_d）；若处于 S5 档则结论反转，但 S5 已被拓扑固定性与 11-06 证伪排除。
- **δ 到「有效周期」的映射采用 E[δ]/T 一阶近似**：未建模相邻 tick 延迟的相关性（连续风暴相关时长）；相关性只会改变折损的时间分布，不改变总量上界（闭式上界已覆盖）。
- **评测器实现细节（内核 hrtimer vs 用户态循环）未知**：两者都继承 CPU 调度延迟，本模型在「唤醒路径」抽象层成立；若评测器使用 `SCHED_FIFO` 类实时调度，CFS 抢占项归零，S2–S4 全部退化为 S0/S1 档（结论只会更强）。
