## 1. 技术体系四大支柱复盘（含官方实证修正）

### 1.1 支柱一：4+2 架构（分段限速框架）

**理论**（`docs/analysis/4plus2-phase-transition-theory.md`）：按文件时长划分传输动力学阶段——
- 1~4.bin（10~80MB）传输窗口 30~50% 处于慢启动爬坡期，刚性限速压制 cwnd 指数增长，需要**弹性突发**；
- 5~6.bin（160/320MB）处于稳态排空期，微突发与背景流叠加会击穿交换机 40 包队列，需要**逐包平滑**。

**11/07 官方实证修正**：该框架的**分层思想**（短流弹性 / 长流平滑）成立，但实现路线被官方数据修正：
- Shot 2（全程 leak：40/40@4k + 36/36@4k）= **124.3683s，全场最佳**——平滑路线在**短文件段同样有效**；
- 含 token_bucket 组件的 Shot 1/3/4/5 = 143.56 / 143.14 / 140.02 / 155.16s——burst 组件在官方环境对应 **143s 档**（三发独立复证）。

**结论**：4+2 架构从「tb+precise 混合」修正为「**非对称漏桶全平滑**」为主线（leak 梯级按文件差异化），tb 突发路线在官方环境被证伪。复测答辩时必须以修正后的版本陈述。

### 1.2 支柱二：非对称令牌桶（已被非对称漏桶接替）

**理论**：1~4.bin 内部按文件长度差分 refill（r40/r38/r36 阶梯，见 `submit_plan_1107_wave2_bypass.json`），理论极限信封 107s。

**官方实证**：Shot 4/5（asym-fast14，Burst=60）= 140.02 / 155.16s，跨场次差 15.14s。「107s 信封」为本地推演值，官方从未接近。**该支柱在官方环境的可用性为零**，其遗产是「按文件差分限速」的构图方法，现由非对称漏桶梯级（如 41-40-37-36、42-41-40-38-37）继承。

### 1.3 支柱三：4% 排空余量律

**理论**：长文件 pacing ≤ 瓶颈带宽的 96%（96M/100M），预留 ~4% 排空余量吸收背景流冲击，使队列深度期望趋近于零（依据：`network-queuing-delay-theory.md`、`monte-carlo-collision-simulation.md`）。

**官方实证**：Shot 2 的 36/36@4k（86.4 Mbps，让出 13.6%）长文件段零异常，与该律同向；Shot 3 的 p98M(98%)+tb 混合=143.14s（被 tb 分量混淆，无干净对照）。**该律与官方数据不矛盾，但缺少官方环境的单变量验证**——列为「待官方单变量确认」条目。

### 1.4 支柱四：1000µs 时钟粒度凸优化

**理论**：pacing 时钟粒度 g 在 g500/g800/g1k/g1500/g2k 邻域存在凸最优，g=1000µs 与平台定时器量子（G≈4000µs 模型）对齐（依据：`configs/` g 系列构型与 `runs/results.jsonl` 统计，`hybrid-statistical-summary.md`）。

**实证现状**：本地 n=1 级样本（g500: 125.441 / g800: 129.498 / g1k 系列）方向一致但**全部 LOW_N**，不满足门禁；且本地校准在 11/06 后被判定失效（36s 全场漂移，见 0062 附录口径）。**列为「本地指向一致、样本不足」条目，复测前需补齐 g1k 邻域样本。**
